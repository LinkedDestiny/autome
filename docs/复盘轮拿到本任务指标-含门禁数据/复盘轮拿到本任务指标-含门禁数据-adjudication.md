### D1-P01 · R1-P01 后续安装会改变已记录步骤的键，R19 的「第二次全沿用」不能成立

- **主张摘要：** 每个步骤的键含两份已装依赖标记。重算只让安装之后的步骤记最终键；安装前（R19 的 Before）、两次安装之间
  （Desktop / Contract / Scripts）的步骤记的是较早状态的键，第二次门禁因键不同必须执行。R19「三步都是 reused」与 B-1 的选定方案矛盾。
- **设计位置：** B-Q1（原第 177–212 行）、M-03 R19、M-03 验收契约。
- **裁决：采纳（事实成立；修法是收窄保证范围并改写 R19，而不是改挂键）。**
- **证据与理由：**
  - 评审用现有算键器推导并实测：安装前后同一步骤的键不同。我复核了 `inputs.mjs:29` `toolchain()` 无条件读取两份标记、
    `calculate()` 把它放进每一步的键，结论成立。R19 的 Before 在第二次不可能沿用。
  - 任务 B-1 / 验-4 的文字是「安装步骤**之后**的每个通过步骤」。Before 不在这个范围。真实场景（T-99：只有 `Desktop install`
    执行了 `npm ci`）里安装之后的全部步骤都落在范围内。
  - 不采纳「把已执行步骤改挂到最终键」：这些步骤没在最终依赖状态下测过，改挂放松 B-2。评审也明确不要求这样做。
  - 两份依赖都首次安装时，夹在两次安装之间的步骤、以及快检里 `Web install` 之前的 `Format` / `Clippy`，同样记当时的状态，
    下一次门禁执行一次后稳定沿用。这是一次性成本，现状下它们本来也要在安装后重跑。省掉它需要改键的组成与版本，超出任务，记 BL-05。
- **修改落点：**
  - B-Q1 新增「保证范围」段，写明最后一次安装之后 / 之前两类步骤的行为；B-1 论证、目标 4 随之收窄。
  - M-03：R19 改为 After 两步 `ran` 且键等于 `--plan` 键、Before 键**不等于**；第二次 After 沿用、Before 执行、无安装；第三次全沿用。
    新增 R23（两次安装：After 沿用，Between 不被错误沿用）。
  - 验收契约：用例数 `ci-reuse` 22→24，第一段 27→29；新增负向对照「把安装前步骤改挂到最终键」。
  - 风险一节加「两次安装之间与安装之前的步骤要多跑一次」。Backlog 加 BL-05。
- **复提计数：** 0。

### D1-P02 · R1-P02 安装失败后的成功准备步骤会重新认可失败安装留下的输入

- **主张摘要：** 重算条件只看「本次准备成功」。`Desktop install` 失败但改了依赖标记后，紧随的 `Build core` 成功会触发重算，
  生效键把失败安装留下的状态当作可信键，后续成功步骤记 `ran`，违反 B-Q2 对失败分支的承诺（应为 `partial -`），
  并且该通过记录可被下一次沿用，跳过安装。
- **设计位置：** B-Q1（重算条件）、B-Q2（失败分支）、M-03 用例。
- **裁决：采纳。**
- **证据与理由：**
  - 反例逐步成立：`steps.sh:12-13` 显示 `Desktop install` 后紧接 `Build core`；`execute_prep` 对每个准备步骤用同一个条件；
    `gate.rs::read_report` 收集失败门禁里的 `ran`，`Store::gate_passes` 允许沿用。评审的隔离实验给出 `partial -` 与 `ran <键>` 的差异。
  - 修法：本进程内引入只增不减的 `ci_prep_failed`。任何准备步骤失败即置位，此后不再重算；生效键停在最后一次可信的键
    （失败之前最后一次成功重算，或 `prepare` 时的键）。失败的安装若改了依赖树，复核键 ≠ 生效键，报 `partial -`；若什么都没改，
    复核键相等，记 `ran`，记录的键描述真实状态，不是漏洞。同一进程内不恢复，只有下一次门禁进程重新 `prepare`（读取磁盘实际状态）
    才恢复。「无关成功准备不能抹去失败」由标志只增不减保证。
  - 覆盖范围：完整门禁所有准备步骤和快检多次 `Web install` / `Build core` 都经过 `execute_prep`，同一处修复；
    测试在共享执行器上用 R24 钉住，快检用 Q20 钉住。
- **修改落点：**
  - B-Q1 重算条件与失败标志规则；B-Q2 改写为「任何准备步骤失败」，并写明哪些步骤不能产生可沿用记录、何时恢复。
  - M-03：新增 R24（按真实顺序「安装失败改依赖 → Build core 成功 → 后续检查成功 → 再跑」，含对照：失败但没改依赖时记 `ran`），
    Q20（快检失败分支）。R22 改称「重算失败分支」。
  - 验收契约：`ci-quick` 名字含「装依赖」 1→2；新增负向对照「去掉 `ci_prep_failed`」。
- **复提计数：** 0。
