# Web 面板按动森风格重做：找回彩色组件与信息层次，补回全局 / 项目级 Loop 配置与技能绑定

## 背景

用户 2026-11-17 看过现在的面板后的原话：「现在的面板 UI 太难看了，且信息展示不够好」「全局和项目级别的循环配置功能没有了。要跟原版一样，支持配置 Loop 的模型，effort，以及需要支持管理项目维度的 Skill（指定 Skill 是项目级别还是全局级别）」。

对照结论：

1. **视觉。** 面板沿用了 animal-island-ui 的令牌（`apps/web/app/styles/tokens.css`），但实现时把这套风格的组件做丢了：没有彩色图案卡片、丝带标题、彩色状态胶囊、进度条，只剩一片米色底配棕色字，层次全靠字号。9 月的成品稿 `docs/design/autome-2.0-desktop-ui.html` 是用户认可的观感。用户已明确：**继续沿用动森风格**，不换审美。
2. **信息展示。** 真实账本上的六个页面截图显示：
   - 总览在没有任务时整页空白；
   - 项目看板「已完成」一列堆了 70 张高卡片，每张带一条对已完成任务没有意义的阶段条；
   - 已合并任务的卡片写着「门禁未跑过」（`apps/web/app/lib/labels.ts:68`，`gate` 为空时的文案），实际都跑过并通过；
   - 任务详情头部拥挤，时间线和文档抢空间，门禁结果与用户的批准不在时间线里，看不出每个阶段花了多久、等了用户多久；
   - 环境页是竖排的原始 UTC 时间戳。
3. **功能缺失。** 旧 Electron 面板有路由图、技能、全局设置三个页面（提交 `e80e9dc1` 删除，旧实现可用 `git show 'e80e9dc1^:apps/desktop/renderer/screens/{routing,skills,settings}.js'` 查看）。Web 面板没有搬过来，现在的项目设置页只有一块只读配置。内核能力都在：`config.get`、`config.validate`、`config.set_role`、`config.reset_role`、`config.set_loop`（都接受可选的 `project_id`）、`skills.list`。

## 设计原型（已经用户确认，是本任务的视觉与信息结构基准）

`docs/design/autome-web-panel-v3.html`——单文件可点击原型，1512×944 一屏，六个页面：总览、项目看板、任务详情、环境、Loop 配置、技能。顶部棕色控制条可切换「有任务在跑 / 空闲」两种演示状态；Loop 配置页可切换全局与项目范围。

用户 2026-11-17 的结论：「没有问题，设计原型通过了」。实现以它为准；原型里的任务 T-101、T-102 和「审计绑定了 autome-v2-simplify」是演示数据，不是需求。

## 要做什么

一次设计、一次评审，按下面分组里程碑实现。

### A 组件与外壳

- A-1 在现有令牌之上补齐原型用到的组件，全站共用：图案卡片的颜色变体（黄 / 青 / 紫 / 蓝 / 绿 / 红 / 虚线）、丝带标题（含小号与颜色变体）、胶囊（描边与实心）、彩色数字块、进度条、主按钮（带立体阴影，只用于主要操作）、分段选择、开关、步进器、输入框、勾选块。
- A-2 外壳：侧栏（品牌、总览、Loop 配置、技能、项目列表带「等你处理 / 进行中」计数、添加项目、驱动状态卡、环境）、顶栏（面包屑、搜索、铃铛、新建任务）。驱动状态卡显示驱动是否在推进与上次检查的相对时间。
- A-3 硬规则不变：全中文（专有名词除外）、1512×944 下页面不出现整页纵向滚动（列与面板内部滚动）、字体离线可用、圆角不小于 12px、不用纯黑、不做深色主题。

### B 总览

- B-1 丝带旁用一句话给结论：有几件事等用户决定、几个在跑、几个在排队；都没有时写「现在没有事情等你」。
- B-2 「等你处理」卡片写明：要用户做什么（批准设计 / 表态 / 处理失败）、任务标题、设计有几个里程碑、评审与裁决的结果、几条 Backlog 待表态、已花费、已用时、已经等了多久；主按钮直达。
- B-3 「进行中」卡片写明：当前角色与轮次、里程碑进度条、正在做哪个里程碑、本轮已跑多久、已用时、已花费；排队中的任务单独一种卡片，写明在等谁。
- B-4 右侧「今天」四个数字块（合并任务数、花费、门禁次数与通过数、等用户的时间）与「最近合并」列表（编号、标题、一个结果胶囊、合并时间、花费）。空闲时这两块照常显示，左侧是两张虚线空状态卡。

### C 项目看板

- C-1 四列用丝带列头。待开始 / 进行中 / 等你处理三列是卡片，信息同 B-2、B-3 的精简版。
- C-2 「已完成」改为按日期分组（今天 / 昨天 / 本周更早 / 更早）的紧凑条目：编号、标题、实现轮数、退回次数、花费；列头旁给累计花费与平均实现轮数。条目点开进任务详情。
- C-3 修掉已合并任务显示「门禁未跑过」的错误。

### D 任务详情

- D-1 头部卡片：状态胶囊、类型与编号、分支、合并提交、操作按钮、标题；一条步骤条，每一步下面写用时与花费，「你批准」是单独一步并写明等了多久；里程碑状态胶囊一行。
- D-2 六个数字块：花费（含几个会话无计费）、总用时（其中等用户多久）、会话数（按工具分）、设计轮、实现轮（含退回次数）、门禁（通过数 / 总数，分快检与合并前）。
- D-3 「执行过程」一行一个事件，按阶段分组、倒序：会话（角色胶囊、轮次、工具与模型、一句话结果、用时、花费）、门禁结果（绿色行，写执行与沿用的步数、用时）、用户的操作（黄色行，写等了多久）、合并。可筛选「只看门禁」「只看退回」。点开会话仍能看日志。
- D-4 右侧保留现有四个页签的全部功能（文档、改动与合并、待你决定、备注与依赖），按新组件重排。

### E Loop 配置（补回的功能）

- E-1 新页面，侧栏有入口，项目看板的「项目设置」也到这里。顶部切换范围：全局默认，或某一个项目。
- E-2 按 Loop 顺序排出六个角色卡片（设计、评审、裁决、实现、审计、复盘），每张显示工具、模型、Effort、绑定技能数、启用开关；固定步骤（任务整理、宿主快检、合并前门禁）与人工停顿是不可配置的虚线卡片。
- E-3 点角色卡片在右侧编辑：启用、工具（Claude Code / Codex）、模型（自由文本，内核不提供模型目录）、Effort（默认 / low / medium / high）、绑定的技能。写入走 `config.set_role`。
- E-4 项目范围下每个角色标明「跟随全局」还是「项目覆盖」，可以「恢复跟随全局」（`config.reset_role`）。
- E-5 双模型纪律：评审与设计、审计与实现的 `工具:模型` 相同时页面当场标红并禁用保存；内核的拒绝仍然原样显示。绑定到看不见该技能的工具同样阻止。
- E-6 Loop 默认值四项：并行任务数、设计轮上限、实现预算系数、单个会话时长上限，走 `config.set_loop`，全局与项目各自可改。
- E-7 现有项目设置页的内容不能丢：Onboarding 状态、门禁与合并等只读配置、移除项目。放在哪由设计轮定（例如 Loop 配置页项目范围下的第二个页签）。

### F 技能（补回的功能）

- F-1 新页面：技能卡片显示名称、来源是全局还是项目、哪些工具看得到、绑定给了哪些角色；可按「全部 / 全局 / 本项目 / 已绑定」筛选、按名称搜索、切换项目。数据来自 `skills.list`。
- F-2 点一个技能在右侧管理绑定：**绑定范围**（全局 · 所有项目，或仅当前项目）与「哪些角色必须使用」。用户已确认「指定 Skill 是项目级别还是全局级别」指的是这条绑定的生效范围；绑定就是角色的技能列表，全局范围写全局配置、项目范围写项目配置，都走 `config.set_role`。
- F-3 角色所用工具看不到该技能时不能勾选并说明原因；项目技能只能绑定在自己的项目里。
- F-4 面板不创建、不编辑、不移动技能文件，只显示来源路径并提供「打开目录」。

### G 其余页面与文案

- G-1 环境页：每项检查一行（状态、名称、路径、版本），驱动单独一张卡；时间一律显示相对时间（「3 秒前」「34 分钟前启动」），悬停可看绝对时间。
- G-2 新建任务、添加项目两个表单页按 A 组的组件重排（现在的单选框与文件选择是浏览器默认样式）。
- G-3 README 的面板截图用 `apps/web/scripts/screenshots.ts` 重新生成。

## 不做什么

- 不换设计风格，不引入新的字体或 UI 框架，不做深色主题。
- 不改 Loop 流程、调度、门禁、协议文本；不升账本结构版本。
- 内核只允许加只读数据（例如总览「今天」的汇总、已完成列表需要的指标字段），而且只有面板服务端从现有方法与事件确实算不出来时才加；写操作只用现有的 `config.*` 方法。
- 不删任何现有功能：铃铛与通知、命令面板、排队调序与依赖、备注与重新打开、Backlog 表态、会话日志、实时更新、内核离线横幅、添加 / 移除项目、Onboarding，全部保留且入口可达。
- 不在面板里创建、编辑或移动技能文件。
- 不动 `.autome/`。Electron 薄壳不改（它加载的就是这个面板）。

## 约束

- 鉴权方式不变：新增的写接口沿用现有的 Host 白名单与 Origin 检查。
- 任务详情首屏文档与单次数据响应不超过 150 KB 的测试（`apps/web/test/task-detail-ssr.test.ts`）继续通过。
- 现有浏览器用例（`apps/web/e2e/`：controls、flows、layout、live、manual-items）与一屏判据随界面改写，覆盖面不缩小；每个改写的用例说明对应原来的哪一条。
- 旧任务的指标里没有门禁字段（T-100 之后才有），相关数字显示为缺失，不显示 0。

## 验收标准

- 验-1 六个页面在 1512×944 下与原型逐屏对照：结构、组件、配色角色一致，没有整页纵向滚动；浏览器用例钉住每页的关键元素（丝带标题、状态颜色、数字块、步骤条等）。
- 验-2 夹具覆盖四种状态：空闲、有任务在跑、有任务等批准、有任务失败；总览的结论句与卡片内容随之正确变化。
- 验-3 已完成列表按日期分组，每行的实现轮数、退回次数、花费与账本一致；已合并任务不再出现「门禁未跑过」。
- 验-4 任务详情的步骤条、六个数字、执行过程与账本的会话、门禁事件、批准事件一致；「等用户多久」由事件时间算出，有测试。
- 验-5 在页面上改全局的某个角色（模型与 Effort），`config.get` 读回新值；在项目范围覆盖同一角色后，该项目显示「项目覆盖」、别的项目不受影响；「恢复跟随全局」后回到全局值。下一个启动的会话用的是新配置（内核测试或夹具证明）。
- 验-6 评审与设计设成同一个 `工具:模型` 时保存被禁用并有说明；绕过页面直接请求时，内核的拒绝原样显示。
- 验-7 技能页列出全局与项目技能；把一个技能按「仅当前项目」绑定给一个角色后，只有该项目的 `config.get` 里出现它；按「全局」绑定后所有项目都出现。工具看不到的角色不能勾选。
- 验-8 「不做什么」里列出的每项现有功能各有一条仍然通过的用例。
- 验-9 `sh scripts/ci-local.sh` 全部通过。
