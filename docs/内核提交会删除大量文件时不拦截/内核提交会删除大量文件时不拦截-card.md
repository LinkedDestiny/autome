# 内核提交会删除大量文件时不拦截，兜底提交收了什么也看不到

## 现象
2026-11-10 T-13 分支上，测试经钩子继承的 GIT_DIR 把任务分支的索引清空，之后内核的兜底提交（`chore(autome): <角色> #n 未提交的剩余改动`）在「删除 515 个文件」的状态上照常提交了 29 次，直到 rebase 冲突才暴露。兜底提交还把会话留下的产物（`apps/web/.vitest/json/output.json`）带进了分支，事后只能翻提交才发现。

## 复现步骤
1. 让假会话在 worktree 里删除 60 个已跟踪文件后正常结束，不自己提交
2. 等内核做兜底提交
3. 看任务状态与 `git log --stat`

## 期望行为
1. 内核在任务 worktree 里做的任何提交（兜底、inputs、补充信息），如果相对 HEAD 会删除超过 50 个已跟踪文件，就不提交，任务进入失败，原因写明「本轮会删除 N 个文件」和前几个路径。
2. 兜底提交照旧提交全部未忽略的改动（包括会话新建、没自己提交的源文件——这是兜底存在的意义，不能收窄），但在事件里列出本次新加入跟踪的文件（最多列 20 个，再多写总数），`autome run` 打印一行。

## 实际行为
删除 515 个文件的提交被照常提交 29 次，没有任何提示；兜底提交带进了什么只能翻提交才知道。

## 环境
- autome-v2 main @ d84cc73，macOS（Darwin 27），已安装的 `~/.local/bin/autome` 由同一提交构建

## 线索
`crates/automed/src/scheduler.rs` 的 sweep 提交（搜「未提交的剩余改动」）调用 `git::commit_paths(&worktree, &["."], …)`；删除数可以在 `git add` 之后用 `git diff --cached --name-status --diff-filter=D` 数出来。上一次尝试（已取消的 T-19）把兜底提交收窄为只提交已跟踪改动，会丢掉会话新建的源文件，这条路不要走。
