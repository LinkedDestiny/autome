## 目标与非目标

**目标**（任务文件 §2）：浏览器用例每轮由宿主按改动跑、失败当轮退回；门禁失败时一次给全材料；实现轮快检带本轮起点；
审计对门禁用例的放行由内核核对；补齐 T-98 的两条测试补强。每一条由脚本或内核代码保证并有测试（约束 2）。

**非目标**：不放宽 Codex 沙箱；不改 `protocol/` 与本任务的协议副本；不改调度、合并队列与门禁时机（合并前门禁仍只在 MergeGate
跑一次，本任务加的是快检命令内部的一个阶段）；不动 `.autome/`；不让 crates 等非 Web 改动触发每轮浏览器用例（A-1 只点名 Web 路径，
见 BL-04）；不识别 cargo / vitest 用例的放行（见 BL-02）；面板与 CLI 不新增显示（见 BL-03）。

## 方案

### 总体：脚本层产出材料，内核层搬运与核对

| 层 | 内容 | 何时生效 |
|---|---|---|
| 项目脚本（`scripts/ci/`、`scripts/ci-quick.sh`、`apps/web/e2e/harness/`、`apps/web/scripts/`） | 快检里的浏览器阶段（A-1、A-2）；Playwright 门禁报告器（A-3、A-4、B-1、B-2 的内容）；门禁用例清单；C-2 的说明行 | 立即：宿主跑的是本分支的脚本，本任务自己后续各轮的快检就会用上 |
| 内核（`crates/`） | 从门禁日志取「失败清单」与「门禁用例清单」两种标记段并交给修复轮（B-1）；B-3 既往记录；C-1 起点；`AUTOME_GATE_DEADLINE`；D-1 放行核对与退回 | 合并、重装内核之后（本任务自己的运行由已安装的旧内核驱动，不受影响） |

两层之间只有一个约定：门禁日志里的**标记段**。内核不知道 Playwright、不假定任何项目路径；任何项目的门禁脚本都可以输出这两种段：

```text
autome-gate-digest begin <步骤名>
…原样交给修复轮的文字…
autome-gate-digest end
autome-gate-cases begin <步骤名>
case	<文件名>	<用例标题>
setup	<准备步骤名>
autome-gate-cases end
```

行首、独占一行；只认首尾都在日志末 256 KiB（现有 `log_window`）内的段，未闭合的段忽略；多个段按出现顺序合并。

### A 浏览器用例每轮由宿主跑

**A-Q1 放在哪一层：快检脚本内的浏览器阶段（方案 a）。** 理由：(1) 内核与调度不变，满足「不改调度、门禁时机」；(2) 宿主跑的是分支里的
`scripts/ci-quick.sh`，本任务自己的 E 组就能拿到宿主真实浏览器结果（E-Q1）；(3) 快检与浏览器的失败在同一个作业、同一份日志和报告里，
退回材料天然合并；(4) Bug FixGate 跑 `( repro ) && ( quick )`，修复轮自动带上浏览器阶段（复现失败时 `&&` 不再跑快检，与现状一致）。
方案 b（新 `Launch` 种类）要动车道、`kind == "quick"` 的 9 处判断与作业文件命名，并且只能在合并后生效，不选。

阶段顺序：现有快检（静态检查 → `ci_quick_start` → 按 120 s 准入的相关测试）全部结束后，进入浏览器阶段。**快检阶段失败也照跑浏览器阶段**
（一次报全）；只有浏览器阶段自己的前置失败时（`Web build` 未通过、`Build core` 失败）记「未跑：Web build 未通过，未跑浏览器用例」。

**A-1 / A-Q2 选哪些用例。** 起点与现有 `quickCandidates()` 相同（`AUTOME_ROUND_START || AUTOME_BASE || CI_QUICK_SINCE`，改动 = diff + 未跟踪文件）；
没有起点时与现状一样注明并不跑。规则依次：

1. **整套**：改动含 `apps/web/e2e/harness/`、`apps/web/playwright.config.ts`、`apps/web/scripts/e2e-preflight.ts`、`apps/web/package.json`、
   `apps/web/package-lock.json`，或 harness 源码引用的 `apps/web/test/fixtures/<文件>`（脚本扫描 harness 源码里的 `test/fixtures/<名>` 得出，
   当前是 `w7-flow.sh`、`process-scan.ts`）。
2. **该文件**：改动含现存的 `apps/web/e2e/<x>.spec.ts`。
3. **改了 `apps/web/app/` 或 `apps/web/server/`**：取本轮证据文件定位当前里程碑——改动里的 `docs/<slug>/evidence/M-xx-r<k>-impl.md`
   （协议规定的实现证据名，`guards.rs` 的 `evidence_file` 保证它存在），读 `docs/<slug>/<slug>.md` 的 `### M-xx 验收契约` 一节的
   「验收命令」行，取其中的 `e2e/<名>.spec.ts`（与 2 合并）。定位不到证据文件、找不到该小节或没有点名 spec 时 → **整套**。
   选择依据：T-98 六次门禁失败里两次是总耗时（只有整套运行才看得到），一次在 D-1（不在当时里程碑点名的 spec 里）；宁可多跑由预算兜底。
4. 其余改动不跑，计划里写「浏览器用例：本轮改动不涉及浏览器用例的输入」。

整套 = `steps.sh` 里 `Web e2e` 那一行，用 `execute_step` 执行（同一命令、同一把键）；子集 = `npm run e2e --prefix apps/web -- e2e/a.spec.ts …`，
走 `ci_partial`，只报 `partial`。两者之前依次：`Web install`（缺才装）、`Build core`（准备步骤）、`Web build`（完整步骤，可沿用也会发布通过记录）。
`--plan` 打印 `e2e<TAB>整套|子集 <文件…>|不跑<TAB><原因>`，测试据此核对选择。

**A-2 / A-Q4 预算与超预算行为。**

- 浏览器阶段**不调用** `ci_quick_admit`，不计入 120 s。自己的预算 `CI_E2E_BUDGET` 缺省 720 s，等于 Playwright 声明的 `globalTimeout`
  （整套自身的上界；实测整套 480 s、单个 spec 含准备 160–240 s）。
- 截止时间：内核新导出 `AUTOME_GATE_DEADLINE`（unix 秒 = 作业开始 + 该作业的生效超时，M-05）；没有时（旧内核，含本任务自己的运行）按
  脚本开始 + 600 s 估计（本项目现配 `quick_timeout_minutes = 10`；写进 README，是对旧内核的保守假设）。
- 进入 Playwright 时的上限 `cap = min(阶段开始 + CI_E2E_BUDGET, 截止 − 60 s) − 现在`；`cap < 240 s`（准备阶段实测最长约 210 s，再少什么都跑不完）
  时整个浏览器阶段记「未跑：剩余 N 秒不够浏览器用例的准备阶段，留给合并前门禁」。
- `cap` 通过环境变量 `CI_E2E_DEADLINE`（epoch 毫秒）交给 `playwright.config.ts`：`globalTimeout = min(720_000, CI_E2E_DEADLINE − 现在)`；
  不改命令，所以不改步骤键。合并前门禁不设这个变量，行为不变。
- 截断时：已跑完而失败的用例 → 步骤失败、当轮退回；未开始与被中断的 → `not_run`「浏览器用例被预算截断（已跑 n / 共 m 条），其余留给合并前门禁」；
  **不发布通过记录**。判定依据是报告器写的 `report.json`（`complete`、`cut`、失败数），由 lib.sh 新增的 `ci_e2e` 包住 `execute_step` / `ci_partial` 判定
  `ran | partial | failed | not_run`，不靠退出码猜。
- 与上一层超时：60 s 余量保证正常情况下内核不会因浏览器阶段杀作业；万一被杀，`kill_group` 收整组进程（约束 7）。在旧的 10 分钟配置下
  单个 spec 放得下（600 − 60 − 快检 ≤ 152 − Web build ≈ 350 s），整套会被截断；「合并后由用户应用」把 `quick_timeout_minutes` 提到 20，整套放得下。

**A-Q3 与 T-97 沿用的衔接（约束 8）。** 只有整套、完整（未截断）、通过且执行后键未变的运行才报 `ran <键> Web e2e`；`CI_E2E_DEADLINE`
只可能**缩短**总超时，完整通过的运行在 720 s 下同样通过，且 A-3 的比较一律按声明值 720 s（见下），所以与合并前门禁在同一份输入上的结果等价。
子集、截断、失败都不发布。命中率如实估计：`Web e2e` 的输入含 `apps/web crates protocol plugins apps/desktop` 与 `scripts` 等全局输入，
之后任何一轮改了这些、或合并前 rebase 带进了 main 在这些目录的改动，键就变了；只有「最后一个改代码的轮次跑了整套」才可能命中。
T-98 的门禁修复轮多数改 harness / spec，按规则 1 会跑整套，若当时已有本机制，第 2–7 次门禁大多可沿用；常规任务的命中率低，合并前门禁照常跑。

**A-3 / A-Q5 总耗时与余量。** 新增报告器 `apps/web/e2e/harness/gate-reporter.ts`（`reporter: [['list'], ['./e2e/harness/gate-reporter.ts']]`）：

- 总耗时 = `FullResult.duration`（runner 从开始到结束，含 globalSetup、用例、globalTeardown；不含 preflight 与 `npm run build`，它们不受
  `globalTimeout` 约束）。上限 = 配置文件声明的 `globalTimeout`（报告器 import `playwright.config.ts` 取声明值；生效值不同时一并打印）。
- 每次运行（含合并前门禁、子集）都打印「总耗时 X 秒，上限 Y 秒（余量 Z%）」并写进 `report.json`。
- 完整运行且 `X > 0.8 × Y`（余量低于 20%）→ `onEnd` 改判 `failed`，写「浏览器用例总耗时 X 秒，上限 Y 秒，余量低于 20%」；恰好 80% 不判失败；
  `globalTimeout` 为 0（不限）只打印；被预算截断的运行不比较。依据：唯一通过的整套 480 / 720 = 67%（余量 33%）；同一用例跨轮相差可到 2 倍
  （D-1 33 / 66 s），总耗时正常波动可到 560 s 左右；20% 的线（576 s）给正常波动留了空间，又在 720 s 硬截断之前报出。子集也比较：子集跑不出
  整套的时长，不会误判。

**A-4 / A-Q6 专设预算过半。** 报告器在 `onEnd` 汇总三类，实测超过预算一半的列进报告（只列出，不判失败）：

- 用例：`TestCase.timeout`（`test.setTimeout` 或缺省 90 s）对 `result.duration`，标注「专设 / 缺省」。
- 断言：`category === 'expect'` 的步骤，按 `location` 读源码那一行，取字面量 `timeout: <数>`（含 `expect.poll(…, { timeout })`、
  `toBeVisible({ timeout })`）；预算是表达式（如 BL-01 的 `Math.max(1, 5000 - …)`）的不比较，只计入「N 处预算不是字面量」。
- 准备步骤：`setup.ts` 对两次 `prepare()` 与服务就绪等待、`teardown.ts` 对整体收尾计时，预算取源码常量（`fixture.ts` 导出
  `PREPARE_TIMEOUT_MS = 150_000`、就绪等待 15 s），逐条追加到 `.autome/output/playwright-gate/harness.jsonl`（setup 开头清空）。
  报告与计时放在 `.autome/output/playwright-gate/`，不放 Playwright 每次清空的 `outputDir`。

`onEnd` 在 globalTeardown 之后、改判决定退出码，已由运行器源码确认（见背景）；M-01 的夹具运行再实测一次。报告器在 `--list` 模式下
（没有结果）只打印清单、不做 A-3 判定。

### B 门禁失败一次报全

**B-1 / B-Q1 三类清单的来源与体量。** 报告器从 reporter 事件（不解析 `list` 文本）得出：

- 失败用例：最终结果 `failed` / `timedOut`；每条「文件:行 标题」+ 错误消息前若干行 + 断言位置（`error.location`）。
- 未执行用例：没有结果的，与 `interrupted` 的（标「被中断，已运行 N 秒」）。
- 非用例错误：`onError` 收到的全部错误原文（globalSetup / teardown 抛错、「Timed out waiting …」、worker 崩溃）。

报告器把这三类连同 B-2 的标注、A-3 行、A-4 列表与各用例耗时打印成一个 `autome-gate-digest` 段（每次运行都打印）。**条目一律列全**；
单条详情先给 1 KB、错误原文 2 KB，整段超过 12 KB 时把详情逐步缩到 300 B，标题与位置始终保留；`report.json` 里是不截的原文。
`summary.mjs` 增加 `playwright` 解析器（读 `report.json` 的失败用例，进现有「失败用例」汇总），`steps.sh` 的 `Web e2e` 行加 `--cases playwright`
（键一次性失效；`apps/web/test/ci-config.test.ts` 的写法钉子同步改）。

### C 实现轮快检带起点

**C-1 / C-Q1 同一个提交。** `launch_session` 把取 `start_heads` 提前到 `build_prompt` 之前（中间没有提交，值不变），同一个值既写进提示词又写进

**C-Q2 配置命令与脚本命令。** 新增可选配置 `[gate] quick_session`：会话里怎样跑同一快检的模板，必须恰好含一个 `{round_start}`，要求配了 `quick`。

  在会话里跑同一检查：`<模板代入 sha>`」。本项目合并后配 `quick_session = 'sh scripts/ci-quick.sh --since {round_start}'`，即任务卡的字面形式。

- Bug 修复轮同样处理（「复现命令和快检」那一句）；工作区项目与取不到起点时保持原句。

另：所有门禁作业导出 `AUTOME_GATE_DEADLINE`（A-2）。

**C-2 / C-Q3 120 秒。** 结论：超预算的主因（整套 `vitest related` 作为单步）已由 `ff87ffa4` 修掉，之后最多超出一个步骤（12–32 s），冷缓存与抢资源
没有证据。预算保持 120 s，语义明确为「准入预算」，不改配置。修法：快检汇总加一行——没超时「快检相关阶段用时 X 秒（准入预算 120 秒）」，
超了时「…最后准入的步骤 <名> 从第 Y 秒开始、用时 Z 秒；之后的 N 步未跑」，让超出有据可查；再加一条测试钉住「Web 相关测试每个候选只含一个测试文件」，
防止整套回流成单步。浏览器阶段不计入（A-2）。

### D 审计放行的口径

**D-Q1 机械识别。** 只看本轮审计写的证据文件（普通审计：本轮新关闭的每个 `M-xx` 的 `evidence/M-xx-r<k>-audit.md`；集成复验：简报指定的那个），
逐行判断，同一行内同时满足：

1. 名字：同 B-3 的匹配词（清单 + 文件名式）；
2. 失败或超时（窄）：`失败|未通过|不通过|超时|ETIMEDOUT|timed out|timeout|FAILED|failed`；
3. 豁免说法：`环境限制|环境问题|环境原因|测试竞态|竞态|偶发|flaky|机器负载|负载高|待宿主|由宿主.{0,16}(复验|实测|确认|验证)|留给合并前门禁`。

满足三条的行，**只有**同时满足「有权限拒绝词（`EPERM|Operation not permitted|权限拒绝|permission denied`）且没有其它失败成因词
（`超时|ETIMEDOUT|timed out|timeout|竞态|偶发|flaky|负载|断言`）」才放行，其余判为违规。后一半是必要的：M-12-r22:9（审计 #14）就是「60 秒 ETIMEDOUT
（…报 ps EPERM）。环境限制」，按「行内有 EPERM 即放行」会被放过。T-98 十行样本的期望：违规 M-04-r7:3、M-10-r19:25、M-12-r22:9；放行 M-13-r24:13；
不涉及其余 6 行。识别不了的写进 Backlog（BL-01、BL-02）。

**D-Q2 「按退回处理」的落点。** 不走会话后检查（那是协议失败）。审计会话结束、会话后检查通过后、计算节点转移之前，内核核对；有违规行时：

1. 用 `autome-domain` 新增的 `status_block::reopen(doc, id, domain)` 改写设计文档：该行 `状态` → `开放`、`reopen` 加 1、`领域` → `gate-waiver`；
   状态块 `status` 若为 `已完成` 改回 `实现中`，`current-milestone` 指向它，`current-milestone-reopens` 同步，`next-action` 写「修复审计放行核对退回的 M-xx（`<证据路径>`）」，
   `convergence-mode` 按协议两条规则只升不降（该行原领域已是 `gate-waiver` 再退回 → `domain-review`；reopen 到 3 → `milestone-review`）。只改这些格子，别的不动。
2. 像「最新证据」指针恢复一样写文件并提交（`chore(autome): 审计放行核对退回 M-xx`），记事件 `audit.waiver_rejected {milestone, evidence, lines}`。
3. 用改写后的状态计算转移：进入实现轮（受实现预算约束），注入新的 `Inject::WaiverRejected{milestone, evidence, lines}`；提示词列出违规行原文与规则
   （只有权限拒绝一类可以放行）。

这复用了协议已有的「退回 `开放`、reopen 加 1」语义，只是由内核执行；协议文本不改。只 EPERM 放行或没有违规行时一切照旧。

## 风险与回退

1. **报告器 API 的实际行为（M-01 首先消除）。** `onEnd` 时机与改判已由 1.64.1 源码确认；仍需实测的是 `interrupted` / 未开始的区分、`onError`
   在总超时与 setup 抛错时各收到什么、`TestStep.location` 是否指向 spec 源码行。M-01 的夹具运行逐项实测；与本设计不符时以实测改报告器，
   不改验收口径。Playwright 升级可能改变这些行为，由 gate-reporter-run 的真实运行守住。
2. **沙箱里能否起 Playwright 运行器。** 运行器只 fork worker、不监听端口，夹具运行预计可在实现会话里跑；不行时按 ★ 交审计，报告器逻辑另有纯函数测试兜底。
3. **每轮多花的宿主时间。** 改 spec 的轮次约 3–4 分钟，跑整套约 8 分钟，在快检之后串行。对照 T-98：6 次门禁失败 2 小时加 18 个额外会话。
   可调 `CI_E2E_BUDGET`；整套回退规则过宽时，可在后续任务改成按路由映射（BL-05）。
4. **抢 CPU。** 浏览器阶段在轻车道，可能与别的任务的全量门禁并行；T-98 审计见过负载 6+ 时 setup ETIMEDOUT。A-4 的预算过半清单会先报出来；
   `quick_concurrency = 1` 限住同车道并发。
5. **放行核对误报。** 本任务的需求编号（`B-3`、`C-2`）与用例编号同形，审计讨论需求时可能误中。代价是多一对实现 / 审计轮，提示词里给出原行；
   连续退回受收敛模式与实现预算约束，不会无限循环。
6. **E-2 判据的时序。** 若整页重验与单路由重验被 React Router 合并成一次请求，BL-01 会偶发变红；M-07 的 5 次重复与负向对照会暴露，届时改为另一种
   判据（在事件批次内断言不存在整页重验请求）并记进证据。
7. **合并前门禁本身被 A-3 拦下。** 若宿主上整套超过 576 s，本任务的合并前门禁会失败；M-01 ★ 的整套实测先给出数字，届时按实测调 `globalTimeout`
   （同时满足 `ci-config.test.ts` 对 CI 作业限时的钉子）。
8. **回退。** 脚本层各里程碑可单独回退；内核层的新行为在没有标记段、没配 `quick_session` 时不出现；D-1 无开关，回退即撤销 M-06 的提交。
