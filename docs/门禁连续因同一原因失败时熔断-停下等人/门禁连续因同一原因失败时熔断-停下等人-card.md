# 门禁连续因同一原因失败时熔断，停下等人

## 背景
T-14 的门禁因为同一个环境问题（缺依赖 `ws`）连续失败 17 次，每次退回实现、会话确认无法修复后结束、门禁再跑，白白耗掉 17 个实现轮，直到预算用完才停下。

## 要做什么
- 为每次失败的门禁计算「失败指纹」：失败的步骤名加上日志尾部归一化后的关键错误行（去掉路径、端口、耗时、哈希等易变部分）。
- 同一任务同一门禁节点连续 N 次（默认 3，`[gate] same_failure_limit` 可改，1–10）指纹相同，就不再退回实现，任务进入失败，原因「门禁连续 N 次因同一原因失败：<指纹摘要>」，并附最近一次日志路径。
- 中间只要有一次门禁通过或指纹不同，计数清零。
- 失败后可用 `rerun` 或 `extend` 继续（与其它失败一致）。

## 不做什么
- 不尝试自动修复环境问题。
- 不改变门禁通过时的任何行为。

## 验收标准
- 单测：指纹对路径、端口、耗时不同但错误相同的两份日志相等；对不同错误不相等。
- e2e：假门禁连续 3 次输出同一错误 → 任务失败，原因含指纹摘要，且第 3 次之后没有再起实现会话。
- e2e：错误交替变化时不熔断，仍按原逻辑退回实现。
- 配置项越界时报中文错误。
- 现有门禁相关测试不改照常通过。
