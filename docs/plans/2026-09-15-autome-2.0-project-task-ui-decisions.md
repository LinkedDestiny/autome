## 1. 项目

项目 = 项目仓库 + Loop 配置 + 任务清单。

### 1.1 项目仓库

- 一个目录。目录不存在就创建；不是 Git 仓库就自动 `git init`。只有一种项目类型，不再区分绿地与已有仓库。
- 选择目录即视为受信，没有单独的「确认受信」步骤。
- 接入后必须初始化（§2.1）。
- 默认分支 = 仓库默认分支，作为所有任务分支的基线与合并目标。
- 项目意图不单独维护，来自仓库内的 AGENTS.md、项目画像与 docs/。
- 并行：按项目控制，默认 3，上限 5。超出的任务自动排队，按提交顺序启动。
- worktree：每个任务一个 `git worktree`，位于项目根 `.worktree/<slug>/`，分支 `autome/<slug>`。合并后删除 worktree 与分支。
- `.worktree/` 与 `.autome/output/` 写入 `.gitignore`。

## 2. Loop 配置

### 2.1 初始化与 Onboarding

- 初始化同 v1 `init.sh`：写入 `.autome/` 脚手架（启动脚本、角色路由、SESSION_SKILL、SCHEDULE.json 等）。自动执行，几秒钟完成，不是 v2 的八阶段状态机。
- 随后进入可跳过的 Onboarding：
  1. 选目录，自动 init（已完成）
  2. Claude Code 在 iTerm2 可见终端中调研仓库，起草项目画像 `docs/agent-project-profile.md` 与 AGENTS.md；空目录时向用户提问项目定位
  3. 用户在应用内确认或编辑产物
  4. 从全局默认复制一份 Loop 配置供用户修改
  5. 完成
- 跳过 = 直接使用全局默认，不起草画像。首个任务的整理节点发现没有画像时自行调研起草并继续，不额外停顿。
- init 与 Onboarding 产物由 Autome 自动提交一个 init commit 到默认分支。这是 Autome 唯一自动提交的场景。

### 2.2 角色与节点

- Loop 流程为 v1 模式的五个角色：设计 plan、评审 review、裁决 adjudicate、实现 impl、审计 audit。
- 每个角色可单独开关。
- SAME-MODEL 闸门保留：review ≠ plan、audit ≠ impl，按 `runtime:model` 字面比较。违反时保存被阻止并在路由图上标红。
- 每个角色字段：启用、CLI（Claude Code / Codex）、模型、Effort（留空用 CLI 默认）、绑定的技能。
- 任务整理、rebase、合并、清理是系统步骤，在路由图上以灰色固定节点显示，不可配置。
- 人工停顿点固定两处：设计定稿后批准、合并前手动点合并（§3.2）。

### 2.3 全局默认与项目覆盖

- 全局默认可改；项目可逐角色覆盖。
- 项目视图只显示生效值和「恢复默认」按钮，不显示逐字段「继承 / 已覆盖」标签。
- 全局可调项：五角色路由、项目并行默认值（3）、设计轮次上限（15）、实现预算系数（5，N = 5 × 初始里程碑数）。终端固定 iTerm2。
- 配置改动即生效：下一个启动的节点读取新配置，正在跑的会话不打断。不做影响预览，不做「只影响未来 Run」。

### 2.4 规则

- 规则 = 仓库内的文件（AGENTS.md、`.autome/rules/*.md` 等），规定每个节点运行时要遵守的项目级规范。随仓库提交。
- 用户直接编辑文件；Autome 只列出，不在应用内编辑。

### 2.5 技能

- Skill 随仓库走：项目自定义 Skill 放仓库内两个 CLI 的原生目录（`.claude/skills/`、`.agents/skills/`）；全局 Skill 在 `~/.claude/skills`、`~/.agents/skills`。Autome 只盘点，不搬运、不在应用内编辑。
- 绑定语义 = 「必须使用」：节点启动时 prompt 显式要求调用绑定的技能。未绑定的节点从全部可见技能中自选。不做「只允许使用这些」的限制。
- 盘点标注每个 Skill 对哪个 CLI 可见；绑定到看不见它的 CLI 时保存阻止并标红，处理方式同 SAME-MODEL。
- 绑定关系存项目根 `.autome/`，随仓库提交。

### 2.6 文件布局与提交规则

- `.autome/` 进仓库以便跨机器同步；`.autome/output/` 忽略。与 v1 一致。
- 配置与运行时状态一律从项目根 `.autome/` 读写；worktree 不需要自己的一份。
- 任务内的 Agent 不允许修改 `.autome/`。
- 用户在界面里改配置只落盘到项目根工作树，提交由用户自己做。

## 3. 任务

### 3.1 输入

- 一句话需求 + 附件 + 仓库内文档引用。附件复制进 worktree 的任务目录并随分支提交。
- 提交即启动（槽位满则排队），不再确认。
- ID = 项目内 T-序号；标题由任务整理节点生成；slug 用作分支名与 worktree 目录名。

### 3.2 生命周期

```
已接收 → 任务整理 → 设计 ⇄ 评审 ⇄ 裁决 → [停：设计定稿，等待批准]
      → 实现 ⇄ 审计 → rebase → [待合并，等待手动合并] → 合并 → 清理 → 完成
```

- 设计定稿停顿：用户在应用内看设计文档、评审、裁决记录。批准则进入实现；驳回并输入意见则回到设计重跑评审裁决，再停。
- 待合并：显示分支、commit 数、文件列表与变更统计、审计结论、rebase 状态。用户手动点「合并到 main」。绝不自动合并。
- rebase：合并前 rebase 到最新默认分支；冲突由实现节点修、审计再审，仍失败才等用户。主工作树有未提交改动时合并失败并提示，不动用户文件。
- 完成 = 合并进默认分支。完成后保留 merge commit、retro 总结、文档链接；worktree 与分支已删。

### 3.3 运行中干预

- 暂停：当前会话跑完后不再启动下一节点。
- 停止：立刻杀掉当前会话。
- 取消：终止任务。
- 不提供「纠偏」输入。要改方向就停止、改需求或规则、重开任务。

### 3.4 Backlog 与争议项

- 面板「待你决定」区列出所有争议项与 Backlog。争议项选一方或写裁定，Backlog 选纳入或忽略。
- 表态在下一个停顿点消费：
  - 设计定稿停顿：有裁定或纳入时，批准变为「带着这些决定再跑一轮设计」，跑完再停一次。
  - 待合并停顿：纳入的 Backlog 变成新里程碑，任务退回实现，审计后回到待合并。用户已接受任务因此拖长。
  - 忽略与裁定写入 retro，随任务文档合并进主分支。
- 不转成新任务。

### 3.5 失败与预算耗尽

- 情形：设计 15 轮耗尽、实现 N 轮耗尽、协议失败、会话崩溃、rebase 冲突无法解。
- 三个按钮都提供：追加轮次继续、从某个节点重跑、取消任务。

### 3.6 面板指标与数据来源

- 主进度 = 里程碑 已完成 / 总数；副指标 = 设计轮次 d/15、实现轮次 k/N。
- 不显示 token 和金额。
- 数据来源为 v1 已有的字段：设计文档头部状态块（status、design-round、implementation-round、current-milestone、reopens、convergence-mode、next-action）、里程碑三态（开放 / 待审 / 已完成）、Backlog、争议项、retro.md、会话启动台账。

## 4. 屏幕

### 4.1 仪表盘（只做监控）

- 顶部：环境异常红横幅，仅异常时出现（如 CLI 登录失效）。
- 「等待我」区：跨项目汇总待批准设计、待合并、待你决定、失败待处置，每张卡带直达按钮。
- 「运行中」区：跨项目所有运行中任务卡：项目、任务、当前节点、轮次、时长、里程碑进度。
- 不做事件流、执行器遥测、预算、内核健康、统计。

### 4.2 项目列表

- 项目卡：名称、目录、默认分支、运行中 / 等待我数量、异常标记。
- 「添加项目」→ 选目录模态框：提示是否 Git、将自动 init、之后进入 Onboarding（可跳过）。
- Onboarding 未完成的项目卡显示「继续 Onboarding」。

### 4.3 项目详情

- 头部：名称、目录、默认分支、并行 n / 上限；「新建任务」。
- 三张卡：仓库（目录、HEAD、活跃 worktree、.autome 状态）、Loop 配置（五角色摘要、覆盖数、并行 / 轮次 / 系数，进入路由图）、规则与技能（规则文件列表、技能数，进入技能页）。
- 任务区分两段：**未完成**（运行中、排队、等待批准、待合并、失败待处置）与**已完成**（已合并进默认分支）。
- 任务卡：ID、标题、状态芯片（节点 + 轮次）、进度条、耗时。等待批准 / 待合并时按钮直接放卡上。未完成段末尾「新建任务」虚线卡。
- 已完成卡为紧凑样式：ID、标题、merge commit、日期、设计 / 实现轮数，带「归档」按钮；段头有「归档全部已完成」与「已归档 N」入口。
- 归档 = 任务目录 `docs/<slug>/` 移入 `docs/.archive/<slug>/`，任务从列表移出；合并记录仍在默认分支历史里。「已归档」抽屉列出归档任务，可恢复（目录移回 docs/）。移动目录只落在默认分支工作树，提交由用户自己做，与改配置同一规则。沿用 v1 的 docs/.archive 约定。

### 4.4 新建任务（抽屉）

- 一句话需求、附件拖放、仓库内文档选择。显示并行占用与排队提示。「创建并启动」。

### 4.5 任务面板

- 头部：ID、标题、状态芯片「节点 + 轮次」、分支、worktree、时长。操作：暂停 / 停止 / 取消、在 iTerm 中查看。
- 节点流 13 节点，当前高亮，两处循环标轮次与预算。
- 第一行卡：当前会话（角色 / CLI 模型 / 开始 / 时长 / 上次产出 / next-action）、里程碑三态列表、原始需求与附件（只读）、待你决定（进入抽屉）。
- 第二行卡：停顿面板（按状态切换：无需操作 / 设计定稿批准 / 待合并 / 失败选项）、产物文件（进入应用内 Markdown 抽屉）、会话历史（每条进入完整日志抽屉）。
- 不内嵌会话实时输出。合并点不做逐行 diff，只有文件列表与统计。

### 4.6 全局设置

- 卡：默认角色路由摘要（进入路由图）、Loop 默认值（并行、设计轮次上限、预算系数）、终端（iTerm2 固定，显示检测状态）、版本。

### 4.7 路由图

- 五角色 Loop 图：任务整理 → 设计 → 评审 ⇄ 裁决 → 设计批准 → 实现 ⇄ 审计 → rebase → 待合并 → 合并 → 清理 → 完成。任务整理 / rebase / 合并 / 清理为灰色固定节点，设计批准 / 待合并为人工节点。通过边实线、驳回边虚线。
- 点角色节点开抽屉：启用、CLI、模型、Effort、绑定的技能、配置来源（全局 / 项目覆盖 + 恢复默认）。
- 顶部切换全局默认 / 当前项目。SAME-MODEL 违规：节点标红、保存按钮禁用并说明原因。

### 4.8 本地环境

- 四项：Git、Claude Code、Codex、iTerm2。每项：存在、版本、路径；CLI 加登录状态。
- 缺失 → 一键安装：在可见终端执行；iTerm2 缺失时用系统 Terminal；Homebrew / npm 缺失先提示安装它们。
- 登录失效 → 「去终端登录」。「重新检测」按钮。

### 4.9 技能

- 只读盘点：范围 = 两个 CLI 的全局目录 + 仓库内目录。每条：名称、来源目录、对哪个 CLI 可见、被哪些角色绑定。操作：打开目录、修改绑定。
- 顶部切换全部 / 当前项目。绑定冲突（角色所用 CLI 看不到该技能）标红。

### 4.10 全局导航

- 侧栏：仪表盘、项目、本地环境、技能、全局设置；最近项目。
- 顶栏：运行中 N、等待我 N，点击到仪表盘。

## 5. 一屏约束

- 以 14 寸 MacBook Pro 逻辑分辩率 1512 × 944 为基准，每个屏幕不得纵向滚动。
- 卡片优先、低密度、全中文，仅保留专有名词与标识符。
