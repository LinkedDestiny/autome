### D1-P01 家目录符号链接可越界探测 —— 驳回

- 主张摘要：`project.probe` 的 `path` 只检查拼写（`~/` 前缀、无 `..`），`$HOME/link -> /` 这样的链接可让 `~/link/<任意>` 探测家目录外的目录，违反「浏览器不能给出任意路径」。
- 设计位置：D-2 第 3–4 项、D-3 `project.probe` 行、K-4。
- 裁决：驳回（不属于六类问题）。
- 证据与理由：
  1. 事实成立（核对 `dispatch.rs` `project_probe` / `shellexpand_home`：只拼接字符串、`is_dir` 跟随链接），但前提是**本机用户自己在 `$HOME` 下建了指向外部的链接**。浏览器可达的写 op 中没有任何一个能在 `$HOME` 下创建链接（`project.add` 两个网关都不可达，上传落在 Autome 自己的上传目录），所以浏览器不能制造这个越界，只能使用用户已经放好的链接。
  2. 约束 5 与 Q1 要求的是「按方法点名、最小的形状约束」；任务文件对 Q1 的措辞也是「形状约束」。设计已满足：绝对路径、相对路径、`~user`、`..` 段全拒。
  3. 评审建议的 realpath 校验会拒绝 `~/code -> /Volumes/外置盘/code` 这类 macOS 上常见的合法链接，直接损害 A-03 与 W9 的用途（把项目加进来）；还引入 TOCTOU，且要在 `gateway.ts` 增加文件系统逻辑，扩大本任务范围。收益（一条只读、仅含「是否存在 / 是否仓库根 / 成员名」的信息）与代价不成比例。
  4. 暴露面与 W9 服务端补全（同在 `$HOME` 范围，同样跟随链接）相同，仍受 Host/Origin 防线约束（§5.5）。
- 修改落点：K-4 补写「这是 D1-P01 的有意决定」及理由；`## Backlog` 追加 B1-01（收紧选项，等用户取舍）。设计行为不变。
- 复提计数：0（首次提出）。
