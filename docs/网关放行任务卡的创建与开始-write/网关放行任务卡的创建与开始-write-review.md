## 非阻塞建议

### S2-01：M-03 的 60000 码元截断对照需要匹配样本长度

- **追溯：**设计 D-8「M-03 逐字到达」（第 237–243 行）与 M-03 验收契约负向对照（第 367 行）。本条只涉及负向样本的构造，不要求新增评审轮。
- **事实与最小反例：**设计要求正文为 65536 个 UTF-8 字节，混有中文、emoji、CRLF、控制字符等，但这不保证 JS `brief.length > 60000`。本轮构造包含全部这些元素、以中文补齐的合法样本，实测为 65536 字节、21883 个 UTF-16 码元；`brief.slice(0, 60000)` 与原文完全相同。因此，该样本无法让“截到 60000 码元”的变异变红。原有 trim、CRLF 规范化和边界 `>=` 对照不因此失效。
- **根因与同类检查范围：**UTF-8 字节边界不能直接推导 UTF-16 截断位置；已核对 D-1/D-4、M-01 字节边界样本及 M-03 的全部负向对照，仅这一固定截断位置需要与样本相配。
- **建议：**实现 M-03 时用 ASCII 补齐主体，使混排样本同时满足 `brief.length > 60000`；或把截断位置设在该样本内部并明确断言原文确实发生变化。保留逐字节比较，不用调整产品上限。由裁决轮决定是否补充设计或记入 Backlog。
