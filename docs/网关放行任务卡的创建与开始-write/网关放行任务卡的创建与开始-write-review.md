## 阻塞问题

### P-01：仅限制路径拼写，仍能经家目录符号链接探测任意外部子目录

- **类别：违反任务目标。**
- **违反要求：**任务文件 §4 硬性约束 5「浏览器不能给出任意路径」；设计 G-3（第 77 行）「路径只能在 `$HOME` 内」、D-3 的 `project.probe` 条款（第 138 行）「浏览器能问的只是家目录内的目录」。
- **设计位置：**D-2 第 3–4 项（第 126–131 行）只检查 `~` / `~/` 前缀、反斜杠、空字符和 `..` 段；D-9（第 246 行）要求不改网关转发层；K-4（第 334–336 行）明确把符号链接越界排除在本任务之外。
- **根因与具体反例：**设 `$HOME/link` 是指向家目录外目录的符号链接，浏览器传 `{method:'project.probe', params:{path:'~/link/target'}}`。它满足 D-2 的全部条件。`crates/automed/src/dispatch.rs:826` 的 `shellexpand_home` 只拼接字符串；第 797–805 行的 `project_probe` 随后对该路径执行 `is_dir`、仓库检查和成员发现，没有家目录边界校验。现有 `apps/web/server/gateway.ts:29–32` 也直接转发，不提供额外约束。如果链接指向 `/`，浏览器便能用 `~/link/<任意子路径>` 选择任意可访问目录。
- **已验证证据：**在 `.autome/output/` 下建立隔离的 `home`、`outside/target` 与 `home/link -> outside`，按 D-2 原文构造谓词，并从当前 `dispatch.rs` 提取原样 `shellexpand_home` 函数编译 Rust 最小验证。`~/link/target` 的谓词结果为 `true`；展开路径的 `is_dir()` 为 `true`；其真实路径不在临时 `home` 内。临时目录已清理。脚本及结果见 `.autome/output/review-1-counterexamples.mjs`、`.autome/output/review-1-counterexamples.txt`。这证明路径边界反例，**不冒充完整 HTTP / automed 集成验收**。
- **影响：**M-02 即使通过目前的 `/etc`、`~/../etc` 等拒绝用例，仍会允许浏览器选择家目录外的探测对象。K-4 的「只读」及 Host/Origin 防线不改变目标目录的位置；也不能用尚未实现的 W9 补全行为证明当前边界成立。
- **同类检查范围：**已检查 D-2、D-3、D-8 的 A-03、D-9、M-02 正反例与 K-4，以及读网关 → `gateway.read` → `project_probe` → `shellexpand_home` 的路径。符号链接作为最终路径或任一中间目录都属于同一根因，应一并处理；目前没有第二个获准接收路径的读方法。
- **建议修改落点：**在 `apps/web` 已获准的服务端范围内明确路径解析与家目录边界校验的位置，保证转交内核的实际目标符合该边界；纯门禁仍保持零依赖。相应调整 D-2/D-3/D-8/D-9/K-4，并增加家目录内普通目录可读、链接指向外部目录被拒的对照。不得只把 G-3 改成「字符串以 `~/` 开头」来绕过任务硬约束，也不需要修改 `crates/` 或新增 W9 页面、路由。

## 非阻塞建议

以下不要求额外评审轮，由裁决轮决定是否进入 Backlog。

### S-01：M-02 的注入样本同步更新数组声明长度

设计第 282–285 行既要求 `[&str; N]` 的 N 等于项数，又要求仅插入 `"task.fake_read",` 后返回该漏项。当前源码 N=17，单独插入后项数为 18。若把长度校验放在共用解析函数内，样本会先因长度失配失败，无法单独检验反向差集。建议注入时同步把 N 改为 18，并另测长度失配。长度断言也可以放在真实源码的独立检查中，因此目前不认定为必然的内部矛盾。

### S-02：标题正确不能单独证明 60KB 正文完整到达内核

D-8 的 A-01（第 223–227 行）把回包标题作为正文完整性的证明，但只保留 `# 网关六十KB缺陷`、截掉后续正文也会得到同样标题与 draft 状态。替身逐字段比较已经提供另一层保障；建议有条件时读取临时项目实际保存的任务卡，与原始正文比对，并收窄该处证据表述。本条属于验证加强，不单独触发复审。

### S-03：区分 A-02 的分支到达证据与成功使用证据

D-8/K-3 的真实请求只预期 409，可证明越过门禁并进入内核错误分支；不能把它写成真实 `task.start`/`task.reply` 成功的证据。设计已给出原样转发替身及内核既有测试的组合依据，故此处不单独阻塞。建议实现证据明确这一区别；如采用不会启动 CLI 的隔离队列夹具，再补成功结果，不得为取证启动实际 Agent 会话。
