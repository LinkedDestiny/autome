00结论先行

真实可控可用的数字员工不是更聪明的提示词，而是围绕 agent 的确定性系统。业界共识与教训可以压成六句话，每句后面都有一手证据。

1状态权威在文件与 git

内核只做确定性编排，agent 的自述永远不是成功判据。

证据：Replit 事故里 agent 在「代码冻结」指令下删库并谎称不可恢复（实际可恢复）；OpenAI Harness 团队把「anything Codex can't access in-context effectively doesn't exist」当作设计原则。

2每轮有开工与收工仪式

一轮只推进一个可验证单元。

证据：Anthropic 把「一次做太多」与「过早宣告完成」列为两大失败模式，解法是 init.sh + 进度文件 + 失败态 feature 清单 + 每会话一个 feature + 结束必 commit。

3退出条件必须可编程

没有机器可读的通过/失败信号就没有 loop。

证据：Ralph Wiggum 循环的作者自认「无程序化退出条件」是它的阿喀琉斯之踵；gstack 的「三次修复失败即停」是另一端。

4审批只卡风险 × 不可逆

铺满审批等于没有审批。

证据：Anthropic 自己承认 Claude Code 的审批放行率高达 93%，并直言这削弱了审查质量。

5权限 / 沙箱 / worktree 正交

三者缺一不可；预算是执行前的硬闸，不是事后的账单。

证据：worktree 只解决文件级并发，不是安全边界；LangChain 多 agent 互调 11 天烧掉 4.7 万美元，Gas Town 实测每小时约 100 美元且产出全部报废。

6反馈成技能只能经人合并

评估靠黄金集与 held-out 回归，自评分永远不作合并依据。

证据：Darwin Gödel Machine 在自改代码时出现过伪造测试通过日志与篡改目标检测器的行为。

对 2.0 方案的意义

这六句话产生 15 条修订与 5 条新增决策（§6）。方案的骨架——内核驱动、outcome 契约、worktree 隔离、双层技能闭环——与业界方向一致；缺的是机械强制：太多约束还写在协议文本里靠 agent 自律。

02最佳实践清单

格式：实践 + 证据 + 落点。已有 指 2.0 方案已覆盖；R# 指 §6 的修订。

A状态与记忆

  • 协议状态权威在文件，编排状态在事件线，两者都可从 git 重建。已有 D9R14 12-factor 第 5 与第 6 因子；Beads 把 issue 与 agent 记忆全放 git，崩溃后可恢复；OpenAI 把执行计划作为 docs/exec-plans/ 版本化制品。
  • 进度与决策记录外置为文件，不依赖对话历史与压缩。R1 Anthropic 的 claude-progress.txt；Codex 25 小时任务的 plans.md 带决策记录防止来回摇摆；Anthropic 上下文工程建议 NOTES.md。
  • 完成位只读：完成清单由初始化产出，执行者只能翻通过位，不得删改条目。R2 Anthropic 原文「It is unacceptable to remove or edit tests because this could lead to missing or buggy functionality」，并指出 JSON 比 Markdown 更不易被模型改写。
  • AGENTS.md 只做目录（约 100 行），知识进 docs/ 并由 linter 保鲜。R7 OpenAI：「Too much guidance becomes non-guidance」「It rots instantly」；Claude Code 文档建议 CLAUDE.md 每行自问「删了会不会出错」。
  • 技能按开放标准分三层渐进披露。已有 L3 agentskills.io：启动只加载 name 与 description，触发才加载全文（建议 <500 行），脚本与引用按需。

B会话边界与分工

  • 一轮会话只推进一个可验证单元，结束时工作树处于可合并状态。已有里程碑R10 Anthropic：「clean state」= mergeable to main，下一个开发者不必先做清理；Backlog.md「一任务一 PR 一上下文窗口」。
  • 开工仪式：校验位置、读进度与状态、跑 init 与烟测，再动手。R1 Anthropic 实测转录顺序：pwd → 进度文件 → feature 清单 → git log → init.sh → 烟测。在坏状态上继续盖只会让问题更糟。
  • 收工仪式：commit、写结构化 outcome、写一行进度。R1 Anthropic；Codex 长任务文档。内核校验三者齐备，缺一标 attention。
  • 评审角色用全新上下文，只看 diff 不看实现者推理，且只读。已有双模型R9 Claude Code 最佳实践；Amp oracle 是只读子 agent；superpowers 两阶段审查（先规格合规再代码质量）。
  • 主循环只做调度与综合，重活派给子会话并只收精炼摘要。已有 Anthropic 上下文工程（子 agent 回传 1–2 千 token）；Ronacher 把失败探索隔离进子 agent。
  • 强耦合的编码任务不要盲目拆成多 agent。R6 Anthropic 多 agent 研究系统博客：token 约为单 agent 的 15 倍，并明确点名 coding 不是 orchestrator-worker 的好场景。

C验证与退出条件

  • 必须给 agent 机器可读的通过/失败信号；验证环境终态，不信产物自述。已有两步裁定R12 Claude Code 最佳实践；Anthropic evals「grade what agent produced, not the path」；Replit 教训。
  • 里程碑验证不过不得进入下一步；回归类验收要求多次全过。R12 Codex 长任务文档；Anthropic evals 的 pass^k（全部成功）用于回归，pass@k（至少一次）用于能力边界。
  • 退出条件必须可编程：轮次上限 + 停滞检测 + 同因三次失败即停。已有预算R3 gstack 的 investigate 铁律；ralph 插件的 --max-iterations；停滞判据可用「工具 + 参数 + 结果重复 2–3 次」。
  • 验收要报「跑了多少」而不只是「过了多少」。已有 §7R12 本仓库 dashboard-mvp 的 retro：同一份代码两次全量，一次 736 用例、一次 822 用例，两次 skipped 都是 0——11 层整层没跑却显全绿。
  • 审计者必须区分「无法复现」与「不存在」。已有 §7 本仓库 retro 建议 3：一个 flake 连跑 12 次不复现，靠日志里的 464.89ms 对 400ms 超时这条因果证据才定位。

D上下文与知识

  • 即时检索优于预加载；技能与文档只放引用，运行时按需读。已有 Anthropic 上下文工程；agentskills 的一层深度引用约定。
  • lint 与门禁的报错文案直接写修复指令，把「人的品味」编码一次后处处生效。R7 OpenAI：「Human taste is captured once, then enforced continuously on every line of code」；自定义 lint 的错误消息专门写成可注入 agent 上下文的修复指令。
  • 每次 agent 犯错，就把它变成一条约束或一个验证脚本，而不是再解释一遍。R13R2 Hashimoto 的 harness engineering 定义；OpenAI「When documentation falls short, we promote the rule into code」。
  • Claude Code 不原生读 AGENTS.md，需 CLAUDE.md 桥接；Codex 原生读 AGENTS.md。R7 两家官方文档；桥接方式是符号链接或在 CLAUDE.md 里 import。

E需求 → 工单 → 任务图

  • 澄清只在决策不可逆或多条路径同样合理时阻塞，其余按显式声明的假设继续。已有提问通道R10 Kiro 的审批门与 Quick Spec；Devin 对模糊需求倾向字面执行的第三方评测；无人值守任务运行时无法反问，消歧信息必须前置。
  • 任务粒度 = 一次独立测试循环、值得让审查者单独把关的最小单元；先定文件级职责边界再反推任务。R10 superpowers 的 writing-plans：步骤级 2–5 分钟一动作（红 → 绿 → 提交），假定执行者无判断力。
  • 验收标准写成可执行检查（EARS / Given-When-Then），描述 What 不描述 How。已有验收命令 Kiro 的 requirements.md 用「WHEN … THE SYSTEM SHALL …」句式；完成靠脚本判定而非 agent 自证。
  • 任务图按依赖分波次调度；执行期新增节点要节流。R10 Kiro 的 wave 调度（波次内并行、波次间串行）；arXiv 2606.01533 实测多 agent DAG 因即兴补丁与重试节点成倍膨胀。
  • 重规划只局部追加，不重建整图。R10 arXiv 2603.14248：高频重规划后计划匹配度反而下降。
  • 执行前检查项目「可编排就绪度」。R11 Symphony 官方：没有幂等 CI、可复现测试、清晰 issue 时，编排只会放大失败率；OpenAI 让应用按 worktree 可启动、日志与指标对 agent 可查。

F多模型分工

  • 跨模型评审有效但方向不对称，路由要由数据决定而非写死。已有双模型强制R9 arXiv 2607.21656（116 题，配对 McNemar 检验）：Claude 审 Codex +18.1 个百分点、回归率 4.3%；Codex 审 Claude −8.6；Claude 自审无提升、成本 +72%。作者自陈仅限单文件竞赛题。另一方面 Chen 等 2025 发现更强的生成者往往也是更好的裁判，自偏好并非全是有害偏差。
  • 评审者只读、不可越权重写；输出结构化区分缺陷与风格。R9 Amp oracle 的只读限制；本仓库协议原则 8 与 9 已有同向条款，但目前靠文本自律。
  • 两个模型意见一致不是正确性的充分证明。已有 共享训练偏见会让一致成为低信号事件；验收命令仍是唯一判据。
  • 成本记账能力不对等。R6R15 Claude Code 的 JSON 终态自带 total_cost_usd / duration_ms / session_id；codex exec 无内建成本字段，用量只在交互式 TUI 的斜杠命令可见。

G可控性

  • 权限管「能不能跑」、沙箱管「跑了碰什么」、worktree 管「并行不互踩」，三者正交。R5 Codex 官方文档（三档 sandbox + 四档 approval，macOS Seatbelt / Linux bubblewrap，是主流工具中唯一默认开启沙箱的）；多个 worktree 仍共享数据库、daemon 与端口。
  • 不可逆操作强制人工审批，且不采信 agent 自证。R4 Replit；2026-07 另一起误配连接串清库事故。
  • 审批按「风险 × 不可逆」分级，只读与常规编辑自动放行。R4 Anthropic auto mode 博客承认 93% 放行率削弱审查；HumanLayer 主张高风险任务在计划阶段签字而非实现阶段逐行卡点。
  • 急停用可编程钩子按命令实时拦截，优先级高于静态规则。已有 kill switchR4 Claude Code hooks 文档的 PreToolUse。
  • 预算是执行前的硬闸：工单级美元上限、轮次上限、单轮超时；成本按任务粒度可见。R6 Paperclip 的 80% 软警告 / 100% 自动暂停；LangChain 4.7 万美元案例（只在账户层监控，异常循环被聚合数据掩盖）；Willison 的 5 美元实验预算。
  • 审计线是 git 与独立台账，不是 Harness 的 checkpoint。R14 Claude Code checkpoint 官方文档：只覆盖 agent 自身编辑工具的改动，不覆盖 bash 的 rm/mv 与多数子 agent 操作。
  • 密钥与网络：生产凭证不进 agent 环境，默认无出网、按需白名单。R5 Codex Cloud 执行阶段默认离线，仅 setup 阶段联网装依赖后即撤销密钥。
  • 技能只允许本地来源，不接第三方市场。R13 ClawHub 约 12–20% 技能带恶意代码，一次「ClawHavoc」事件涉及 1184 个恶意技能；技能是可执行代码目录而非沙箱脚本。

H反馈 → 技能闭环

  • 反馈结构化：触发场景 + 期望行为 + 证据，而非自由文本。已有 D7 Warp：一点来自资深工程师的详细反馈胜过大量二元点赞，因为二元信号说不出「为什么」。
  • 提案先进暂存区，人审后合并；一个提案一个失败模式。已有 D6R13 Hermes 的 write_approval 把写入暂存到 pending 目录等待批准；Warp 的最小编辑使 diff 极小、审查成本趋近于零。
  • 评估靠黄金集与 held-out 回归，只接受帕累托改进；自评分与 LLM judge 不作合并依据。R13 Self-Harness 的 held-in / held-out 双轨；GEPA 的帕累托前沿；DGM 出现伪造测试通过日志与为骗过检测器而删除标记的行为；LLM judge 在专家领域与人的一致率仅 60–68%。
  • 技能版本化可回滚，未用技能定期归档。R13 DGM 维护多样化「祖先」档案；Hermes 的 Curator 对 90 天未用技能自动归档。
  • 让 LLM 自写断言会把当前 bug 锁定成预期行为。R13 ICST 2025；黄金集断言必须人工校验。

I成本与并行

  • 并行数是成本与失控的乘数，默认要小。R6 Gas Town 每小时约 100 美元、产出的 PR 全部质量不合格需关闭；Vibe Kanban 单机超过 4 并发即降速；worktree 只解决文件级冲突，两个 agent 改同一逻辑仍会语义冲突。
  • 维护类工作用唤醒模型而非常驻。R8 Paperclip 的 heartbeat 内核（唤醒队列触发短执行窗口，同一 agent 多次唤醒会合并）；OpenAI 的后台垃圾回收任务；Warp 的定时 improver。

04来源间的分歧与我们的取舍

调研里有六处来源彼此矛盾。列出分歧本身，以及我们选哪一边、为什么。

#分歧我们的取舍
1配置文件精简 vs 累积。Anthropic 主张 CLAUDE.md 极简；Hashimoto 鼓励 AGENTS.md 逐条累积踩坑AGENTS.md 精简为目录（R7），踩坑教训进 docs/ 约定文件与门禁脚本，由 improver 提案维护，两者都不无限增长
2自建循环 vs 结构化框架。12-factor 与 Ronacher 反对框架式 loop；superpowers 与 gstack 提供强制多阶段流程内核是自建的确定性 workflow（12-factor 路线），playbook 是可替换的流程定义（superpowers 路线），两者分层不冲突
3自主放权程度。Ralph 与 Willison 主张无人值守换产出；Claude Code 与 gstack 强调检查点默认全自动 + 三类必卡点（R4），放权程度由工单级设置决定，不做全局二选一
4退出条件工程化程度。除 Ralph 外全部主张可编程退出全部机械化进内核（R3）
5并行的价值。Agent Teams 与 Gas Town 展示倍增；成本分析提醒线性乃至非线性开销并行只在任务图证明独立时开启，默认 2（R6）
6双模型评审的必要性。跨模型论文支持，自偏好研究持保留保留强制分模型，但路由预设可切换并由指标页数据裁决（R9）

05与 2.0 方案骨架的对照

已与业界一致

内核事件流与两步裁定（12-factor、OpenAI）· outcome 契约与提问通道（12-factor 第 7 因子）· worktree 隔离（业界收敛方案）· 双层技能闭环（Warp、Hermes）· 双模型纪律（跨模型论文）· 任务文件快照原则（协议版本固定）

主要缺口

约束多写在协议文本里靠 agent 自律（完成位、写域、停滞、验证口径），缺内核层的机械强制；没有沙箱与密钥策略；预算只有轮次没有美元；没有会话仪式；没有就绪度检查；没有维护类周期任务；反馈闭环缺暂存区、held-out 与回滚

这正是 §6 的十五条修订要补齐的。
