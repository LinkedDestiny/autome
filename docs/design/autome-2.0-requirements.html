1. 产品定位

Autome 2.0 是一个 macOS 桌面应用。用户在自己的 Git 仓库上，用一句话需求驱动 Claude Code 与 Codex 按「设计 → 评审 → 裁决 → 实现 → 审计」的 Loop 自主完成开发。用户只在两处介入：批准设计、点合并。

目标用户：单人开发者或小团队技术负责人。本机已安装 Claude Code 与 Codex，日常使用 Git 与 iTerm2。

核心价值：

  1. 多任务并行，每个任务在自己的 worktree 里，不互相干扰，也不碰用户当前工作树。
  2. 生成侧与评测侧强制使用不同模型（SAME-MODEL 纪律），避免自产自评。
  3. 人只做两件事：定方向（批准设计）、收成果（合并）。
  4. 配置、规则、技能、任务文档全部随仓库走，多机同步靠 Git。

2. 术语

术语 含义
项目 一个本地目录加它的 Git 仓库。Autome 的顶层管理单位。
默认分支 仓库默认分支（如 main）。任务分支从它切出，最终合并回它。
worktree git worktree。每个任务一个，位于项目根 .worktree/<slug>/。
任务 用户输入的一句话需求及其整个生命周期。项目内编号 T-序号。
角色 Loop 的五个 AI 角色：设计 plan、评审 review、裁决 adjudicate、实现 impl、审计 audit。
节点 任务生命周期的一步。包括五个角色节点、系统步骤和人工停顿。
会话 一次 CLI 进程运行。一个角色节点的一轮对应一次会话。
轮次 设计循环轮数 d（裁决加一）、实现循环轮数 k（实现加一）。
里程碑 设计文档中的 M-01…M-N，三态：开放、待审、已完成。
Backlog 非阻塞改进建议，等用户处置。
争议项 评审与设计双方复提两次后冻结的分歧，等用户裁定。
停顿点 任务等待用户的位置：设计定稿后、合并前。
Onboarding 添加项目后可跳过的引导流程。
规则 仓库内规定 Agent 行为的文件。
技能 Claude Code 与 Codex 原生技能目录中的 Skill。
绑定 指定某角色启动时必须使用某技能。

3. 范围

3.1 2.0 做什么

  • 项目的添加、初始化、Onboarding、配置、归档。
  • 任务的创建、并行调度、五角色 Loop、两处人工停顿、rebase 与手动合并、归档。
  • 全局与项目两级 Loop 配置，五角色的 CLI、模型、Effort、启用、技能绑定。
  • 本地环境四项检测与一键安装。
  • 技能只读盘点与角色绑定。
  • 桌面端九块屏幕。

3.2 2.0 不做什么

  • 不做 09-13 方案中的任务契约、任务图、要求覆盖矩阵、证据收据、证书、交付演练、交付核对。
  • 不自动合并，不推送远端，不发 PR。
  • 不内嵌终端，不展示会话实时输出流。
  • 不做技能市场、隔离审计、技能库。
  • 不显示 token 与金额，不做统计报表。
  • 不做跨项目的并行上限，只做项目内并行控制。
  • 不做运行中「纠偏」输入。
  • 不支持 Windows 与 Linux，不做多用户。

4. 功能需求

4.1 项目

P-01 添加项目。 用户选择一个目录。目录不存在则创建；不是 Git 仓库则执行 git init，默认分支 main。 验收：对空目录执行添加后，目录是 Git 仓库，.gitignore 含 .worktree/ 与 .autome/output/，存在 .autome/ 脚手架，且默认分支上有一个 init commit。

P-02 选择即受信。 添加项目没有单独的「确认受信」步骤。 验收：添加流程中不出现受信确认界面。

P-03 默认分支识别。 以仓库默认分支为任务基线与合并目标。 验收：对默认分支为 master 的仓库，任务分支从 master 切出并合并回 master。

P-04 项目并行。 每个项目有并行上限，默认取全局默认值 3，最大 5。超出的任务自动排队，按提交顺序启动。 验收：并行 3 的项目提交第 4 个任务时，任务显示「排队 #1」；任一任务释放槽位后它自动启动。

P-05 worktree。 每个任务一个 worktree，路径 .worktree/<slug>/，分支 autome/<slug>。合并或取消后删除 worktree 与分支。 验收：运行中任务的 worktree 存在；合并后 git worktree list 不含该任务，分支已删除。

P-06 项目意图。 不单独维护产品意图。Agent 从 AGENTS.md、项目画像与 docs/ 获得项目背景。 验收：项目页没有意图编辑入口。

P-07 项目列表。 每张项目卡显示名称、目录、默认分支、运行中数量、等待我数量、异常标记。Onboarding 未完成的项目显示「继续 Onboarding」。 验收：见设计稿「我的项目」屏。

P-08 移除项目。 从 Autome 移除登记，不删除目录、不改仓库内容。存在运行中任务时拒绝移除。 验收：移除后目录与 .autome/ 原样保留。

4.2 Loop 配置

C-01 初始化。 添加项目后自动写入 .autome/ 脚手架：项目配置、启动脚本、会话技能说明、规则目录。幂等，重复执行不覆盖用户改动。 验收：连续两次初始化，第二次不修改已存在文件。

C-02 Onboarding。 五步：选目录并 init、Claude Code 起草项目画像与 AGENTS.md、用户在应用内确认或编辑、从全局默认复制 Loop 配置供修改、完成。任何一步可跳过剩余步骤。Claude Code 在 iTerm2 可见终端中运行；空目录时向用户提问项目定位。 验收：跳过后项目立即可建任务并使用全局默认配置；完成后仓库中存在 docs/agent-project-profile.md 与 AGENTS.md。

C-03 init commit。 init 与 Onboarding 产物由 Autome 自动提交到默认分支。这是 Autome 唯一在默认分支上自动创建的非合并提交。 验收：init commit 包含 .autome/、.gitignore 及 Onboarding 产物；此后界面改配置不产生自动提交。

C-04 五角色字段。 每个角色可配置：启用、CLI（Claude Code 或 Codex）、模型、Effort（留空用 CLI 默认）、绑定的技能。 验收：路由图节点抽屉包含以上五项。

C-05 角色开关。 每个角色单独开关。评审关闭时裁决无输入，自动跳过；审计关闭时实现节点的「待审」视为完成。 验收：关闭评审后任务从设计直接进入设计定稿停顿；关闭审计后里程碑全部待审即进入 rebase。

C-06 SAME-MODEL 纪律。 评审与设计、审计与实现不得使用相同的 CLI 与模型组合。违反时保存被阻止，路由图节点标红并说明原因。 验收：把审计改成与实现相同的组合后，保存按钮禁用，节点显示红色。

C-07 全局默认与项目覆盖。 全局默认可改。项目可逐角色覆盖，项目视图只显示生效值与「恢复默认」。 验收：项目覆盖实现角色后，其他角色随全局默认变化而变化，实现角色不变；点恢复默认后跟随全局。

C-08 全局可调项。 五角色路由、项目并行默认值、设计轮次上限（默认 15）、实现预算系数（默认 5，N = 系数 × 初始里程碑数）。终端固定 iTerm2。 验收：全局设置页只有这些可调项。

C-09 改动即生效。 配置改动在下一个启动的会话生效，正在运行的会话不打断。 验收：运行中任务改模型后，当前会话继续，下一节点使用新模型。

C-10 规则。 规则是仓库内文件（AGENTS.md、.autome/rules/*.md）。Autome 只列出，不在应用内编辑。 验收：项目页显示规则文件列表；点击在编辑器中打开。

C-11 提交规则。 配置在项目根 .autome/ 随仓库提交；.autome/output/ 忽略。界面改配置只落盘，提交由用户自己做。任务内 Agent 不得修改 .autome/。 验收：会话技能说明中含禁止修改 .autome/ 的条款；改配置后 git status 显示未提交改动。

4.3 任务

T-01 输入。 一句话需求，加可选附件与仓库内文档引用。附件复制进 worktree 的任务目录并随分支提交。 验收：带附件创建任务后，docs/<slug>/attachments/ 在任务分支上存在。

T-02 提交即启动。 创建后不再确认。有槽位立即启动任务整理，无槽位排队。ID 为项目内 T-序号，标题由任务整理节点生成，slug 用作分支与 worktree 名。 验收：创建后 3 秒内任务出现在列表，状态为「任务整理」或「排队」。

T-03 生命周期。 节点顺序固定：

已接收 → 任务整理 → 设计 ⇄ 评审 ⇄ 裁决 → [设计定稿，等待批准]
      → 实现 ⇄ 审计 → rebase → [待合并，等待手动合并] → 合并 → 清理 → 完成

验收：任务面板节点流按此顺序显示，当前节点高亮，两处循环显示轮次与预算。

T-04 设计定稿停顿。 裁决判定设计定稿后任务停下。用户可在应用内阅读设计文档、评审、裁决记录。批准进入实现；驳回并输入意见后回到设计，重跑评审与裁决，再停。 验收：驳回后设计轮次加一，新一轮评审的输入包含用户意见。

T-05 待合并停顿。 rebase 干净且审计通过后任务停下，显示分支、commit 数、文件列表与变更统计、审计结论、rebase 状态。合并只能由用户点击触发。 验收：不存在任何自动合并路径；点「合并到 main」前默认分支不变。

T-06 rebase 与冲突。 合并前 rebase 到最新默认分支。冲突时由实现节点修复，审计再审，仍失败才等用户。 验收：构造冲突后，任务进入实现节点并携带冲突文件列表；修复通过审计后回到待合并。

T-07 合并与完成。 合并前置条件：主工作树无未提交改动、任务分支已在最新默认分支之上。不满足时合并失败并提示，不改动用户文件。合并后删除 worktree 与分支。完成 = 已合并进默认分支。 验收：主工作树有未提交改动时点合并，提示失败且文件未被触碰。

T-08 运行中干预。 暂停：当前会话跑完后不再启动下一节点。停止：立刻结束当前会话。取消：终止任务，删除 worktree 与分支，任务文档复制到 docs/.archive/<slug>/。不提供纠偏输入。 验收：暂停后当前会话进程仍在，会话结束后无新会话；停止后会话进程退出。

T-09 Backlog 与争议项。 面板列出所有争议项与 Backlog。争议项选一方或写裁定；Backlog 选纳入或忽略。表态在下一个停顿点消费：设计定稿停顿有裁定或纳入时，批准变为「带着决定再跑一轮设计」；待合并停顿纳入的 Backlog 变为新里程碑，任务退回实现，审计后回到待合并。忽略与裁定写入 retro。不转成新任务。 验收：待合并时纳入一条 Backlog，任务回到实现，设计文档新增里程碑，完成后再次进入待合并。

T-10 失败与预算耗尽。 情形：设计轮次耗尽、实现预算耗尽、协议失败、会话崩溃、rebase 冲突无法解。用户可选：追加轮次继续、从某个节点重跑、取消任务。 验收：实现预算耗尽后三个按钮可用；追加 5 轮后预算上限加 5 并从实现节点继续。

T-11 进度指标。 主进度 = 里程碑已完成数 / 总数；副指标 = 设计轮次 d/15、实现轮次 k/N。不显示 token 与金额。 验收：任务卡与面板显示上述指标，任何位置不出现 token 或金额。

T-12 已完成与归档。 项目页任务区分未完成、已完成两段。已完成任务可归档：docs/<slug>/ 移入 docs/.archive/<slug>/，任务移出列表。可从「已归档」恢复。目录移动只落在默认分支工作树，不自动提交。 验收：归档后列表不含该任务，docs/.archive/<slug>/ 存在；恢复后目录移回。

T-13 任务产物。 每个任务在 docs/<slug>/ 下产生：任务文件、设计文档、设计评审、裁决记录、实现审计、retro。设计文档头部维护状态块，是任务状态的事实来源。 验收：面板产物区列出六个文件；设计文档在应用内渲染。

T-14 会话历史。 每次会话一条记录：角色、CLI 与模型、开始时间、时长、结果，可点开看完整日志。 验收：日志内容与 .autome/output/sessions/ 下的文件一致。

4.4 界面

U-01 导航。 侧栏：仪表盘、项目、本地环境、技能、全局设置、最近项目。顶栏：运行中 N、等待我 N。 U-02 仪表盘。 只做监控：环境异常横幅（仅异常时）、「等待我」跨项目汇总、「运行中」跨项目任务卡。不做事件流、遥测、统计。 U-03 项目列表。 见 P-07。 U-04 项目详情。 头部信息与新建任务；仓库、Loop 配置、规则与技能三卡；未完成与已完成两段任务卡；已完成带归档。 U-05 新建任务抽屉。 一句话需求、附件拖放、仓库内文档选择、并行占用与排队提示、创建并启动。 U-06 任务面板。 头部、13 节点流、当前会话、里程碑、原始需求、待你决定、停顿面板、产物、会话历史。停顿面板按状态显示无需操作、批准设计、合并、失败选项四种内容。 U-07 全局设置。 默认角色路由摘要、Loop 默认值、终端、关于。 U-08 路由图。 五角色 Loop 图，灰色固定节点与黄色人工节点不可编辑，点角色节点开配置抽屉，顶部切换全局与项目。 U-09 本地环境。 四项卡片与被引用情况。 U-10 技能。 盘点卡片，含来源、可见 CLI、绑定角色、打开目录、修改绑定。 U-11 一屏与语言。 以 1512 × 944 逻辑像素为基准，每屏不纵向滚动。界面全中文，只保留专有名词与标识符。

验收：U-01 至 U-10 以设计稿 autome-2.0-desktop-ui.html 为准；U-11 用 Playwright 逐屏测量 scrollHeight 不大于 clientHeight。

4.5 本地环境

E-01 检测项。 只检测 Git、Claude Code、Codex、iTerm2。每项显示存在、版本、路径；两个 CLI 加登录状态。 E-02 一键安装。 缺失项提供一键安装，命令在可见终端执行。iTerm2 缺失时用系统 Terminal。Homebrew 或 npm 缺失时先提示安装它们。 E-03 登录。 登录失效时提供「去终端登录」，打开终端执行对应 CLI 的登录命令，完成后自动重新检测。 E-04 重新检测。 手动按钮；应用回到前台时自动检测。 E-05 异常横幅。 CLI 缺失或登录失效时，仪表盘顶部显示红色横幅并指向本地环境页。

验收：卸载 iTerm2 后本地环境页显示缺失与一键安装；点击后终端中出现安装命令。

4.6 技能

S-01 盘点范围。 ~/.claude/skills、~/.agents/skills 与各项目仓库内 .claude/skills、.agents/skills。只读。 S-02 可见性。 标注每个技能对 Claude Code 与 Codex 是否可见。 S-03 绑定语义。 绑定 = 该角色启动时必须使用此技能。未绑定的角色从全部可见技能自选。不做「只允许」限制。 S-04 冲突阻止。 技能绑定到看不见它的 CLI 所用角色时，保存被阻止并标红。 S-05 存储。 绑定关系存项目根 .autome/，随仓库提交。 S-06 只读。 不在应用内创建或编辑技能，只提供打开目录。

验收：把只在 ~/.claude/skills 的技能绑定给使用 Codex 的评审角色，保存按钮禁用并显示原因。

5. 非功能需求

  • 响应：界面操作 200 毫秒内有反馈；任务状态变化 3 秒内反映到界面。
  • 安全边界：不改用户主工作树内容（除 init commit、用户触发的合并、归档与取消时的目录移动）；不推送远端；不自动合并；Agent 不得修改 .autome/；取消任务只删 worktree 与分支。
  • 可恢复：应用重启后从仓库文件与本地台账恢复任务状态；正在 iTerm2 中运行的会话不受应用重启影响。
  • 可观察：每次会话有独立日志文件；retro 每轮追加一行。
  • 数据位置：项目配置在仓库 .autome/；全局默认在 ~/.autome/；项目登记、任务索引、会话台账在 ~/Library/Application Support/Autome/。

6. 端到端验收场景

  1. 空目录添加项目，跳过 Onboarding，创建任务，设计定稿停顿批准，实现审计通过，待合并，手动合并，任务完成，归档。
  2. 项目并行 3，提交第 4 个任务进入排队，第 1 个完成后第 4 个自动启动。
  3. 两个任务修改同一文件，后合并者 rebase 冲突，实现节点修复，审计通过，回到待合并。
  4. 把审计改为与实现相同的模型，保存被阻止；改回后保存成功。
  5. Codex 登录失效，仪表盘出现横幅，去终端登录后横幅消失。
  6. 待合并时纳入一条 Backlog，任务退回实现并新增里程碑，完成后再次待合并。
  7. 实现预算耗尽，选择追加 5 轮，任务继续并完成。
  8. 主工作树有未提交改动时点合并，提示失败，文件未变。
  9. 设计定稿时驳回并附意见，设计重跑一轮后再次停顿，新设计包含对意见的处理。
  10. 应用重启期间一个会话在 iTerm2 中结束，重启后任务状态正确推进到下一节点。
