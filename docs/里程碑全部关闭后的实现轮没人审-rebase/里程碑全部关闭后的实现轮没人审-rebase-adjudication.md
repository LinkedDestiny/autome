### D1-P01（对应 R1-P01）rebase 范围算法把实际冲突解决改动判为空

- 主张：`--cherry-pick` 的两条公式漏审两类冲突解决：自己的产品提交在冲突中被丢弃（右侧为空，且没有右侧目录外提交就不写事件）；patch-id 归一化空白，改写后的提交被判等价。
- 设计位置：方案 §1 条件 (c)(d)、§2、§3、R1。类别：关键事实错误。
- 裁决：**采纳**。
- 证据：评审日志 `dropped-only.log` 显示「列出」为空、「消失」只有旧 F，最终产品为 `upstream`；这与设计 §1 (d) 只看目录外提交的口径直接矛盾。第二例是 git patch-id 的已知行为（忽略空白）。
- 修改落点：§1 (c)(d) 把「消失」纳入；§2 新增「冲突文件的保守纳入」（`B1..H1` 中被重写或新增且改到冲突文件的提交一律列出，冲突文件取自 `carried_inject`）与「消失不只是显示项」（带 `paths`、`stat`）；§3 事件 `dropped` 增加 `paths` / `stat`。M-01 用例 11→16，新增 `…conflict_that_drops_the_product_commit_is_still_integration` 与 `…conflict_file_commit_with_an_equivalent_patch_id_is_still_listed`，负向对照同步。冲突文件未知的会话自行 rebase 情形作为残余入 Backlog B-06。
- 复提计数：0。

### D1-P02（对应 R1-P02）文件名存在不能证明本轮新增了独立证据

- 主张：守卫只看 `M-*-r<k>-audit.md` 是否存在，实现轮正常递增 k 并预写同名文件时，审计什么都不写也被放行，违反约束 5、6。
- 设计位置：方案 §7、B-03、R2。类别：违反任务目标。
- 裁决：**采纳**。
- 证据：现有 e2e 替身 `World::EVIDENCE` 在每步同时写 `-impl.md` 与 `-audit.md`，反例由设计的判定直接推导；`evidence_filenames` 只枚举文件名。
- 修改落点：§4 在审计 `session.started` 的 `integration` 里增加 `evidence_stamp`（简报指定路径在审计启动时的存在 / `mtime_ns` / 长度，重试与 `rerun` 沿用第一次审计尝试的值）；§7 把「有证据」改为简报指定的那个路径在审计会话期间被写入过（`apply_guards` 比较后传入 `evidence_touched`，`guards::check` 仍是纯函数）。选 mtime 而不是内容比较，是因为现有 e2e 的替身审计会重写同样内容的同名文件，既有测试不允许为此改动。R2、B-03 重写。M-02 `guards` 33→34、`integration_wiring` 4→5，M-04 的「无证据」用例改为实现步骤预写审计证据、审计不写。
- 复提计数：0。

### D1-P03（对应 R1-P03）已确认集成改动后读取统计失败仍取消审计对象

- 主张：设计把「统计读取失败」与「没有集成改动」都归为不写事件，只写 warning，后续守卫看不到 E，旧免查分支放行。
- 设计位置：方案 §3、§4、§7 `None` 分支、R6。类别：违反任务目标。
- 裁决：**采纳**。
- 证据：设计原文「计算失败（Git 报错）→ 不写事件」，已确认的集成条件与展示信息的读取没有区分，反例由该分支直接推导。
- 修改落点：§3 改为两级处理——判定所需事实读取失败时失败关闭（沿用 `apply_guards` 的 `?` 路径，任务停下可 `rerun`，不当作空轮）；已确认集成轮之后的展示信息（`stat`、测试文件扫描）失败时事件照常写、字段写「读取失败」。R6 同步。不新增 `FailureReason`。M-01 新增 `…unreadable_range_fails_closed`、`…a_stat_failure_keeps_the_range`。该路径是否确实停下，由实现轮核对并写进证据。
- 复提计数：0。

### D1-P04（对应 R1-P04）内联测试只改准备条件时测试文件清单漏列

- 设计位置：方案 §2 测试文件规则。类别：违反任务目标（约束 9「宁可多列」）。
