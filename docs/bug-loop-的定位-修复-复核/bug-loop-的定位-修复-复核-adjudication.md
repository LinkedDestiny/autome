### D1-P01 共用渲染同时修正整理轮附件路径，超出范围

- **主张摘要。** 设计让共用的 `render_inputs` 一律取附件文件名，整理轮在有绝对路径附件时的渲染从
  `…/attachments//tmp/source/crash.log` 变成 `…/attachments/crash.log`，违反任务第 4 节「需求 Loop 的 prompt 文本与渲染
  结果都不变」与 C1「范围不扩大」。
- **设计位置。** 方案 1、方案 5 改动清单、launcher 单测 5、M-01 负向对照、风险 R1、人工验收清单第 1 项、`next-action`。
- **裁决。** 采纳。
- **证据或理由。** 核对 `crates/automed/src/launcher.rs` 的 `intake_prompt`：附件行是 `format!("- {}/attachments/{a}", …)` 直接拼
  存储原值；设计要求改变的正是这个输出。设计原先靠「任务卡优先」和合并前人工确认来扩大范围，但任务第 4 节是明文禁止，
  且任务卡自身也写「不改需求 Loop 的 prompt」，没有用户表态授权越界；范围授权也不适合推迟到人工验收清单。评审的修法同时满足
  「复用整理轮 inputs 渲染」（第 3 节第 1 项）与第 4 节，不必回到两套内联拼接。
- **修改落点。** 设计文档：`render_inputs` 只拼装、附件显示名由调用方定（整理轮传原值，Bug 侧传副本文件名）；单测 5 改为固定
  整理轮按存储原值渲染（防以后越界统一）；M-01 负向对照、R1、人工验收清单、`next-action` 同步；新增非目标一条、目标 G1b、
  Backlog B-05（整理轮绝对路径缺陷留给另行授权的任务）。里程碑拆分、验收命令与预期数量不变。
- **复提计数。** 0。
