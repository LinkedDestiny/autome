# 审计简报没写出证据文件的确切路径，审计按自己的序号命名导致协议失败

## 现象
实现轮因门禁失败多跑了一轮后，实现轮号 k 与审计序号不再相同。审计把证据写成 `M-03-r3-audit.md`（按「审计 #3」），内核期望 `M-03-r4-audit.md`（按实现轮号），判「本轮没有留下证据文件」→ 协议失败。

## 复现步骤
1. 让实现轮 #3 门禁失败、实现轮 #4 通过，进入审计 #3
2. 假审计按简报文件名 `brief/audit-3.md` 的序号写 `M-xx-r3-audit.md`
3. 看会话结束后的判定

## 期望行为
审计简报（以及实现简报）明确写出本轮证据文件的完整路径，例如「本轮证据写到 `docs/<slug>/evidence/M-03-r4-audit.md`」，会话不需要自己推算 k。

## 实际行为
T-15 审计 #3 因此失败（2026-11-11 01:03），审计内容本身是通过的，只能手工改名后重跑。

## 环境
- autome-v2 main @ fd519b2，macOS（Darwin 27），已安装的 `~/.local/bin/autome` 由同一提交构建
- 项目 autome-v2 自身由 tmux 里的 `autome run` 驱动

## 线索
`crates/automed/src/brief.rs` 生成简报处；`guards.rs` 的 `evidence_file` 用的就是 `round`。协议里 `r<k>` 指实现轮号，而简报文件名用的是角色自己的序号，二者容易混。
