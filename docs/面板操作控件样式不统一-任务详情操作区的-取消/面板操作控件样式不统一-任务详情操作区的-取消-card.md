# 面板操作控件样式不统一：任务详情操作区的「取消」是裸链接，多数按钮没走统一按钮样式

## 现象

用户 2026-11-18 在已安装的面板（提交 `4507a9cf`，真实账本，1512×944）上反馈「发现了新的样式问题」，并截了任务详情页头右侧的操作区：「撤销授权」是一个大按钮，旁边的「取消」只是两个裸字，贴在上沿，看不出能点。操作者把操作区的几种状态拍了一遍，并清点了全站的按钮写法，问题有 4 处，是同一个根因。截图见附件。

共同根因（先修根因，不要逐处打补丁）：面板里**并存两套按钮样式**，而且**充当操作的链接和展开入口没有按钮样式**。
- 统一的按钮是 `apps/web/app/components/ui/button.tsx`（类名 `.btn` / `.btn-primary` / `.btn-text` / `.btn-sm`，胶囊形，38px / 30px）。全站只有约 14 处在用。
- 其余约 48 处 `<button>` 没带任何类名，落到 `app.css` 第 23 行的裸 `button { … }` 兜底样式上：小圆角矩形、输入框底色、上下 10px 内边距，实际高约 45px。
- 用 `<Link>` 或 `<details><summary>` 充当操作的地方完全没有样式，只是一行文字。

1. **任务详情操作区**（用户截图；附件 `user-ops.png`、`ops-running.png`、`task-detail.png`）：「撤销授权」「暂停」「停止」是 45px 高的兜底按钮；「取消」是 22px 高的裸链接，顶端对齐，没有边框和底色。「停止」「取消」这类不可逆操作与普通操作长得一样。
2. **取消确认**（附件 `ops-cancel-confirm.png`）：点「取消」后，「确认取消这个任务」是普通按钮，没有危险提示的样子；「返回」是裸链接，掉到按钮下面一行。
3. **带表单的操作**（`task-ops-view.tsx` 第 32 行，任务失败、等你批准或等你补充信息时出现）：「驳回」「补充信息」「重跑」「追加轮次」「改建成需求」是 `<details><summary>`，显示成带小三角的一行文字，与同一排的按钮混在一起。
4. **全站**：同一屏里两种按钮并存。例如任务详情里展开的会话日志，「暂停滚动」「跳到最新」是 45px 的兜底按钮，而同页时间线筛选、顶栏「新建任务卡」是胶囊按钮（附件 `task-detail.png`）。裸按钮的分布：`components/session-log.tsx` 6、`routes/loop.tsx` 5、`components/settings-page.tsx` 5、`components/task-decisions.tsx` 4、`routes/projects.new.tsx` 3、`routes/projects.$id.tasks.new.tsx` 3、`routes/env.tsx` 3、`components/task-ops-view.tsx` 3、`components/queue-controls.tsx` 3、`components/bell.tsx` 3、`components/task-dependencies.tsx` 2，以及 `routes/skills.tsx`、`routes/projects.$id.tsx`、`components/task-notes.tsx`、`components/shell.tsx`、`components/project-alerts.tsx`、`components/loop-defaults.tsx`、`components/command-palette.tsx` 各 1（本任务排在 T-123 之后，T-123 会先改掉其中铃铛、抽屉等几处，以开工时的代码为准重新清点）。

## 复现

仓库根目录执行，面板用隔离夹具，不碰真实账本：

```sh
sh scripts/ci/install-node.sh apps/web
npm run build --prefix apps/web
cd apps/web && npx playwright test e2e/action-controls.spec.ts
```

`e2e/action-controls.spec.ts` 是定位轮要新建的回归测试文件（见「线索」）。也可以直接起面板目视：`autome web start` 后打开任一运行中任务的详情页看页头右侧操作区，点「取消」看确认态，展开一条会话日志看「暂停滚动」「跳到最新」。

## 期望

0. 根因：全站只有一套按钮。所有操作控件（`<button>`、充当操作的链接、展开表单的入口）都走 `components/ui/button.tsx` 或它的类名；需要时给它补变体与用法（见下），不要在各页面另写按钮样式。`app.css` 里裸 `button { … }` 的兜底样式改成与统一按钮一致的外观（或在全部迁移后删除），保证以后漏写类名的按钮也不会长成另一种样子。
   - 变体：主按钮（立体阴影，一个区域最多一个）、普通、文字、**危险**（新增：用于不可逆操作，颜色只用现有的 `--animal-error` / `--animal-error-active` 令牌，不用纯红、不加立体阴影）。
   - 尺寸：默认 38px；紧凑场景（页头操作区、时间线与日志行内、卡片内、抽屉、铃铛、页签内容区）用小号 30px。
   - 自带样式的专用控件不在此列：分段选择、开关、步进器的加减、页签、纯图标按钮、时间线与日志的展开三角。
1. 任务详情操作区：所有操作等高（小号 30px）、同一行、垂直居中；「取消」是按钮；「停止」「取消」用危险变体。操作区在页头里只占一行，页头总高度不得比现在高，时间线「一屏至少 10 行」的现有断言必须继续通过。
2. 取消确认：「确认取消这个任务」用危险变体，「返回」是普通或文字按钮，两者同一行。
3. 带表单的操作：入口与同排按钮同一外观、同一高度；点开后表单在操作区内向下展开，入口保持在原位，不把其它操作挤乱。
4. 全站不再有落到兜底样式上的按钮；同一屏内同一层级的按钮外观一致。表单页的提交按钮用默认尺寸的主按钮，其余按上面的尺寸规则。

## 线索

- **回归测试写进新文件** `apps/web/e2e/action-controls.spec.ts`，**不要把断言补在已有的测试文件里**（内核的「修正回归测试」流程只对新建的测试文件可用，补在已有文件里一旦要修就走不下去）。新文件复用 `./harness/browser.ts` 与 `./harness/fixture.ts`。如果仓库里有清点 e2e 文件或用例的清单、单测或门禁配置，定位轮同一轮一起更新。
- 建议的断言：
  - 任务详情（夹具里取一个运行中的任务）：操作区内全部 `[data-op]` 控件高度一致（差 ≤ 1px）且不超过 32px，顶边一致（差 ≤ 1px）；「取消」的计算样式有可见边框或底色、圆角与其它按钮相同。
  - 点「取消」后：确认按钮与「返回」顶边一致（同一行），高度一致。
  - 全站清扫：依次打开总览、项目看板、任务详情（展开一条会话日志）、Loop 配置、技能、环境、新建任务、添加项目、项目设置，页面上每个可见的 `button`（排除上面列的专用控件，按类名或 `role` 排除并在用例里写明排除清单）高度只能是 30±1 或 38±1px、圆角不小于 12px。修复前这条在多页会红。
- 回归测试第一次就要写对：整套 `npx playwright test` 一起跑一遍（夹具里的数据会被前面的用例改变，不要写死条数）；宿主门禁环境的 PATH 与你的 shell 不同，不要依赖本机装了哪些工具；确认修复前是红的，原因是样式断言而不是环境问题。
- 不要改 `data-testid`、`data-op`、按钮文案与表单字段名：`apps/web/e2e/flows.spec.ts`、`controls.spec.ts`、`live.spec.ts` 靠它们点击。把链接换成按钮外观时保留 `<Link>` 的跳转行为（「取消」是跳到 `?confirm=cancel`，不是直接提交）。
- 改动任何结构或类名时，同一轮把 `apps/web/test` 与 `apps/web/e2e` 里期待旧值的断言一起改完。
- 这些都是浏览器里才能判的外观。定位轮与修复轮请直接在 worktree 里实跑浏览器用例，并对操作区、取消确认、带表单的操作（夹具里造一个失败的任务）、会话日志各截一张图目视确认。
- 硬规则不变：全中文、1512×944 不出现整页纵向滚动、圆角不小于 12px、不用纯黑、立体阴影只用于主按钮、保持动森风格令牌。只改 `apps/web`，不动内核。
- 复核轮在沙箱里跑不了浏览器用例，这是已知限制，记为验证缺口即可；浏览器用例由宿主门禁实跑。
