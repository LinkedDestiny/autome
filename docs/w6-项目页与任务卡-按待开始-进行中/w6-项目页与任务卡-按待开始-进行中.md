## 方案

### 1. 项目页与看板（R-01）

新文件 `app/components/board-data.ts`，全部是纯函数，外加一个 loader 辅助：

- `boardColumns(tasks, now)`：每个任务调 `columnOf(task.state)`，`null` 的不显示。列顺序固定 `todo, running, needs_you, done`，列名取 `COLUMN_LABELS`。
  列内按 id 数字倒序；已完成列按 `completed_at` 倒序。本文件**不出现**任何状态字面量（`'draft'`、`'queued'`……）——状态到列只有 `task-columns.ts` 一份，测试会扫源码。
- 已完成列：`now - completed_at ≤ 14 × 24 h` 的放进 `recent`，其余（含 `completed_at` 为空）放进 `older`。`older` 默认折叠，列尾一个链接
  「查看全部（n）」指向 `?done=all`，展开后同一位置是「收起」指向去掉该查询串的地址。展开是一次普通导航，loader 读取 `done=all` 才取更早已完成卡的详情（§2，D1-P01）；
  折叠态不渲染 `older` 的卡，也就不取它们的详情。
- `filterBoard(columns, kind)`：`kind ∈ {all, feature, bug}`，只过滤每列的卡片，不改列归属。列标题在 `all` 下是 `待开始（5）`，在筛选下是 `待开始（2 / 5）`——
  分母永远是未筛选的总数，与 `countByColumn` 一致。筛选状态放组件状态（`useState`），不进 URL：换筛选不触发 loader，「只影响显示」由构造保证。
- `now`：loader 返回 `now`（ISO 字符串），SSR 与首次水合用同一个值；挂载后 `useNow(now)` 每 60 秒更新一次本地时钟，只用来重算「运行 N 分钟」与 14 天分界，
  不保存任何任务字段（计划 §5.2）。

路由 `app/routes/projects.$id.tsx`：`loader` 调 `loadBoard(services, params.id)`；`action` 处理「开始」（§4）；`shouldRevalidate` 见 §5。
内核离线或 `project.get` 被拒时，loader 不抛错，返回 `{ error }`，页面在主区域原样显示这句中文，外壳照常。
页面布局：标题行（项目名、筛选三按钮、「新建任务卡」链接到 `newTaskHref(id)`）+ 四列网格；外壳已经限定主区域高度，看板 `min-height: 0`，
每列的 `.board-column-body` `overflow-y: auto`，页面本身不滚动。

### 2. 任务卡与取数（R-02、R-06）

**取数方案 `loadBoard`：**

1. `project.get({project_id})` 一次：任务列表、`config.bug.fix_rounds`。
2. 对「需要详情」的任务各一次 `task.get`，`Promise.all` 并发。需要详情 = `columnOf` 非空，且状态不是 `draft`（`draft` 没跑过任何东西，门禁固定「未跑过」），
   且若是 `done`，则它在 `recent`（近 14 天），或 URL 带 `done=all`（此时 `older` 也取）。已完成卡与其它卡一样显示真实的最近一次门禁结果（A-02，D1-P01）：
   `task.get` 对完成任务照常返回 `gate`（实测 `task-get-T-1.json`：`gate.ok=true`、`gate.node=main_check`、`exit_code=0`），合并提交作为附加信息另行显示。
3. 只有当某个详情的 `retry` 非空时，再调一次 `dashboard.get` 取 `cooldowns`。没有重试就不调——它会全量遍历并可能启动环境探测。
4. `unread.unreadByTask(needYouKinds())` 一次（本地 SQLite，不经内核）。

调用次数 = `1 + N_live + N_done (+1)`：`N_live` 是待开始里的排队任务、进行中、等你处理三列之和，受 `parallel` 与待处理数约束；`N_done` 是近 14 天已完成数
（展开 `done=all` 后为全部已完成数）。折叠态不随历史任务总数增长。按实测，`N_live + N_done = 7` 时一次 loader 约 50 ms。根 loader 的 N+1（W5 B-01）不在本任务修。

`needYouKinds()` 在 `board-data.ts` 里由 `NOTIFICATION_RULES.filter(rule => rule.level === 'need_you').map(rule => rule.kind)` 算出，不抄列表。
`project_alert` 没有 `task_id`，`unreadByTask` 自然不计它。

**`UnreadSource`** = `Pick<ReturnType<typeof openWebStore>, 'unreadByTask'>`，`main.ts` 把整个 `store` 传进去，类型只暴露这一个方法。
没有库对象时（现有测试那样不传），卡片角标只显示「等你处理」字样，不显示数字。

**卡片视图 `cardView(task, detail, ctx)`**（`app/components/task-card-model.ts`，纯函数；`ctx = { now, fixRounds, cooldowns, unread }`）：

### 3. 上传（R-03 附件）

**传输：** 浏览器对每个文件 `fetch('POST /api/uploads', { headers: { 'Content-Type': 'application/octet-stream', 'X-Autome-Filename': encodeURIComponent(file.name) }, body: file })`。
不用 multipart，不加依赖；`express.json` 只认 `application/json`，不会吃掉这个请求体。

**`server/uploads-limits.ts`**（不 import 任何 Node 模块，前端也引用）：`UPLOAD_MAX_BYTES = 10 * 1024 * 1024`、`UPLOAD_MAX_FILES = 10`。
理由：截图、日志片段、短录屏都在 10 MB 以内；附件会被 Agent 读进上下文，更大的文件只会浪费上下文；10 个上限远低于白名单的 256，留给正文本身。
常量只写这一处，服务端校验与表单提示同引用它（测试扫源码确认数值只出现一次）。

**`server/uploads.ts` 的 `createUploads(home)`：**

- `receive({ name, stream, contentLength })`：先清洗文件名——URL 解码后按 `/`、`\` 取最后一段，去掉控制字符，去掉开头的点；结果为空、`.`、`..` 时拒绝
  「文件名无效」；UTF-8 超过 200 字节时截短主名、保留扩展名。`contentLength > UPLOAD_MAX_BYTES` 立刻拒绝（413）；否则流式写到
  `<home>/web/uploads/.partial-<uuid>/<名字>`，边写边计数，超限即中止、删目录、413；写完后把目录改名为 `<uuid>`。返回 `{ id, name, size }`。
  413 的提示：`附件「<名字>」超过单个 10 MB 的上限`（数值由常量格式化）。
- `resolve(id)`：`id` 必须匹配小写 UUID；目录 `<home>/web/uploads/<id>` 下恰好一个普通文件才返回它的绝对路径，否则 `null`。`.partial-*` 永远不可解析。
  路径用 `join(home, 'web', 'uploads', id, name)` 拼，和网关检查用同一个 `home` 字符串，不做 `realpath`（macOS 的 `/var` ↔ `/private/var` 会让两边不一致）。
- `describe(id)`：`{ name, size } | null`，供 action 查重名与个数。
- **不删除**暂存文件：草稿与排队任务要等到真正开始才复制（实测），而面板不知道一个任务何时完成了复制。清理进 Backlog B-01。

**端点：** `http.ts` 在 `securityMiddleware` 之后注册 `app.post('/api/uploads', …)`，所以 Host、Origin 检查与其它 `/api` 一样先过。
`Content-Type` 不是 `application/octet-stream` → 415「上传请求必须是文件原始字节」；成功 200 `{ok: true, payload: {id, name, size}}`；
失败 `{ok: false, error}`，400 / 413。没有 `uploads` 时不注册（与现有 `notifications` 的写法一致）。

**客户端 `app/components/upload-client.ts`：** `uploadFile(fetch, file)` 先按同一常量预检（只为早点提示），再发请求，原样返回服务端的中文错误。
