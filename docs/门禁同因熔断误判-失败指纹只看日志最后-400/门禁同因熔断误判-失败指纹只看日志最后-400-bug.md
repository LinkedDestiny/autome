## 现象

定位基线 HEAD 为 `b4d6d6f`（包含任务卡所述 `bf399db`）。本仓库自身是 Cargo workspace，实际成员包为 `crates/autome-domain`、`crates/automed` 和 `crates/autome-cli`；不是另含多个 Git 成员仓库的工作区，`repos: .` 指当前仓库。复现命令直接从当前 worktree 根目录执行。

合成日志稳定复现任务卡中的指纹 `b886b56b86275c1a`：两个不同 Rust 失败的指纹完全相同，摘要都误指向 Web 成功用例打印的 `Error: 内核在回复前退出 (code=null, signal=null)`。三个不同失败依次调用实际 `streak` 后得到 `(1,false)、(2,false)、(3,true)`，第三次误熔断。

任务卡所述历史 T-50 原始日志在当前 worktree 不存在，未独立核验历史三次运行及修复提交的实际效果；以上结论来自当前代码与可重复的合成日志实验。

## 复现

新增 `crates/autome-domain/tests/gate_failure_window.rs`，使用公开的 `fingerprint` 与 `streak`，无网络、文件读取、时钟或进程时序依赖。日志遵循 `scripts/ci-local.sh` 的步骤头和失败汇总结构：早期 Rust panic 和失败用例之后，插入 420 行成功输出，再插入成功 Web 用例的 Error 日志和 Rust 步骤失败汇总。所有输入均小于 256 KiB。

运行状态块中的命令，两次均正常编译并以退出码 101 结束，结果一致：2 通过、3 失败。失败来自断言，不是依赖缺失或命令执行错误。

- `gate_failure_window_distinguishes_early_failures`：期望不同失败 ID 不同，实际都是 `b886b56b86275c1a`。
- `gate_failure_window_summary_belongs_to_failed_step`：期望摘要包含失败步骤与真实失败行，实际取成功步骤的 Error；在无 420 行填充的短日志对照中即失败。
- `gate_failure_window_different_failures_do_not_trip`：期望三次各为 `(1,false)`，实际第三次 `(3,true)`。
- `gate_failure_window_same_failure_still_trips`：通过，同一失败三次正常熔断，防止以后通过禁用熔断掩盖问题。
- `gate_failure_window_short_logs_distinguish_failures`：通过，仅去掉后续大量输出即可区分失败，排除本例由归一化碰撞造成的可能。

完整输出位于 `.autome/output/gate-failure-window-run1.log` 和 `.autome/output/gate-failure-window-run2.log`，不提交原始输出。

## 根因分析

1. `crates/automed/src/gate.rs:345` 的 `log_window` 先限定最后 256 KiB，再限定最后 400 行；`crates/autome-domain/src/gate_failure.rs:176` 的 `fingerprint` 又独立限定最后 400 行。任意一层保留旧截断都可能丢失前面步骤的真实失败。
2. `scripts/ci-local.sh:59` 的 `run` 在失败时记录步骤名称后继续运行后续步骤，最后汇总失败步骤。Rust 测试在 Desktop/Web 之前，因此失败汇总仍在窗口内，但具体失败信息已在窗口外。
3. `gate_failure.rs` 的 `key_line` 接受泛化的 Error/panicked 关键词，未将关键行归属到失败步骤；也不专门识别 `test … FAILED`。摘要从整个窗口倒序优先选以错误词开头的行，导致成功测试的 Error 胜过真实 panic。短日志也错误，说明仅删除 400 行限制不能修复摘要归属。
4. `scheduler.rs:3714` 把文件窗口传给 `fingerprint`，再把 ID 传给 `streak`。后者按相同 ID 累加的行为符合设计，问题源于输入身份已丢失区分信息，不是计数本身。

对于任务卡给出的约 150 KiB 完整日志，256 KiB 容量在数值上足够，去掉行数截断即可保留全量；当前没有历史文件，不能将该大小视为已实测。对于超过字节上限的日志，仅保留最后 256 KiB 仍可能丢失早期失败；后续修复需要明确有界读取与失败证据保留策略，不能宣称扩大行窗口能覆盖任意长度日志。

现有单测 `window_is_last_400_lines` 固化了旧截断行为，与新验收目标存在冲突，修复轮需相应处理旧行为测试，但不得删除或弱化本轮新增回归测试。当前回归覆盖领域指纹与连续计数，未运行文件读取层或完整调度器端到端验收；文件读取层问题由代码调用链确认，修复时仍须验证该层。
