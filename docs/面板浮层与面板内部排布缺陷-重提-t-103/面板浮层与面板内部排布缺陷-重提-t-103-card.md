# 面板浮层与面板内部排布缺陷：两个抽屉、铃铛、任务详情页签区等 9 处

## 现象

T-102（提交 `4507a9cf`）合并后，在真实账本上以 1512×944 打开已安装的面板，用户 2026-11-18 的反馈原话：「不少弹窗的排版布局存在问题」，并截了角色抽屉与任务详情文档页签两处。操作者把全部浮层和页签逐个拍了一遍，对照 T-102 的验收标准（验-2、验-5）与已确认原型 `docs/design/autome-web-panel-v3.html`，共 9 处排布不对。截图见附件（真实账本，1512×944）。

**这是 T-103 的重提。** T-103 已经做完修复并经过一轮独立复核，卡在内核的一个缺陷上无法继续（见「线索」第一条），所以取消重提。上次的全部提交留在 `refs/keep/t103-fix-7a595e22`，本任务应当复用，不要从零重做。

共同根因（先修根因，不要逐处打补丁）：浮层和面板的**内容区没有统一的排布规则**。抽屉内容区 `.drawer-body` 只管滚动，不管子元素怎么排，字段就按行内元素挤在一起；页签内容区、铃铛面板没有统一的内边距与行间距；浮层里的按钮都用了页面级的大号按钮。

1. **角色抽屉字段挤在一行**（用户截图；附件 `loop-drawer.png`、`loop-drawer-proj.png`）。「启用」开关、工具分段选择、「模型」两个字排在同一行，模型输入框掉到下一行，看不出「模型」是哪个框的标签。项目范围下，底部「保存」与「恢复跟随全局」两个按钮贴在一起没有间隔。
2. **技能抽屉**（附件 `skills-click.png`、`skill-drawer-global.png`）：
   - 「哪些角色必须使用」里被置灰的角色行，角色名被同一行的原因文字挤成一字一行（「评 / 审」）。
   - 描述长的技能（如 `agent-browser`），完整描述加两条来源把「绑定范围」和角色勾选推到屏幕外；这个抽屉的主要用途是绑定角色，却要先滚动。
   - 每条来源下面一个通栏的大号「打开目录」按钮。
3. **技能卡片的「未绑定」胶囊被拉成整行宽**（附件 `skills-proj.png`）。
4. **环境页**（附件 `env.png`）：正常的工具仍占两行，「查看安装方法」单独一行；页头「4 项检查全部正常」和「28 秒前检测过」分两行；页面底部的驱动卡露出一半，要内部滚动才能看全。T-102 验-5 要求四个工具都正常时整页不用内部滚动。
5. **任务详情页头阅读顺序乱**（附件 `task.png`）：标题被放到第一行右侧，和「已合并 · 需求 · 编号 · 项目名」同一行；分支名与提交号掉到第二行左侧。
6. **任务详情右侧页签区没有间距**（用户截图；附件 `task-docs-tab.png`）：页签条、「文档 来自默认分支（主检出）」说明、文档胶囊三行紧贴在一起；胶囊行没有左右内边距，最后一个「复盘教训」贴到面板右边缘；「文档」两个字既是页签又在下一行重复一遍。
7. **铃铛面板**（附件 `bell.png`）：「全部已读」「标为已读」是页面级大号按钮；每条通知约 150px 高，一屏只看到两条半；通知标题里的长文字不截断。
8. **项目范围的「恢复跟随全局」不分情况都能点**（附件 `loop-drawer-proj.png`）：四项默认值卡片写着「与全局相同」，下面仍有一个可点的「恢复跟随全局」；角色卡写着「跟随全局」，抽屉底部的「恢复跟随全局」同样可点。
9. **备注与依赖页签把 Markdown 当纯文本显示**：操作者备注里的反引号、列表符号原样显示成一大段，没有分段和列表（同一页的文档页签是渲染过的）。

## 复现

仓库根目录执行，面板用隔离夹具，不碰真实账本：

```sh
sh scripts/ci/install-node.sh apps/web
npm run build --prefix apps/web
cd apps/web && npx playwright test e2e/overlay-layout.spec.ts
```

`e2e/overlay-layout.spec.ts` 是定位轮要新建的回归测试文件（见「线索」）。现有 `e2e/layout.spec.ts` 全部通过，说明它没有覆盖这些排布。也可以直接起面板目视：`autome web start` 后打开 `/loop` 与 `/loop?project=<项目 id>` 点任一角色卡、`/skills` 点 `agent-browser`、`/skills?project=<项目 id>` 点一个项目技能、`/env`、总览点铃铛、任一已完成任务的详情页切四个页签。

## 期望

0. 根因：抽屉内容区、页签内容区、铃铛面板各有一条统一规则——子元素纵向排开、块之间固定间距（不小于 10px）、左右内边距与所在面板一致；浮层内的次要按钮一律用小号按钮。之后新加的浮层内容不单独写样式也不会挤在一起。
1. 角色抽屉的字段自上而下逐行排开：启用开关一行；工具分段选择一行；「模型」标签在输入框上方，输入框占满抽屉内容宽度；Effort 分段选择一行（带「Effort」标签）；「绑定的技能」与「添加技能」各一行。底部按钮之间间隔不小于 8px。
2. 技能抽屉：
   - 内容顺序改为：绑定范围 → 角色勾选 → 描述 → 来源。打开抽屉不滚动就能看到全部六个角色和「保存绑定」。
   - 角色名始终横排在一行内；置灰原因换到角色名下方一行或同一行右侧省略（`title` 放全文），不得挤压角色名；置灰行需要更宽时独占整行。
   - 描述默认最多 4 行，超出时给「展开」入口；「打开目录」改成路径同一行右侧的小号按钮。
3. 「未绑定」「已绑定角色名」胶囊宽度随文字，靠左，不拉伸。
4. 环境页：正常的工具每个只占一行（状态点、名称、路径、状态文字、「查看安装方法」入口、版本胶囊），点开后说明在该行下方展开；页头两句状态同一行；四个工具都正常、驱动卡不超过 3 行时，整页不需要内部滚动，驱动卡完整可见。
5. 任务详情页头：第一行是状态胶囊、类型、编号、项目、分支、提交号（靠左，一行内，过长时分支名省略）；第二行是标题，靠左；有操作时操作区仍在右侧跨两行。页头总高度不得比现在高，时间线「一屏至少 10 行」的现有断言必须继续通过。
6. 任务详情右侧页签区：四个页签的内容区统一内边距（左右不小于 12px）；页签条、来源说明、文档胶囊行之间各留不小于 8px；胶囊换行时行距不小于 6px，最右一枚不贴边；去掉重复的「文档」二字，只留「来自默认分支（主检出）」这句说明。
7. 铃铛面板：按钮用小号；每条通知不超过 96px（标题最多两行省略、任务名一行省略、时间与「标为已读」同一行）；1512×944 下一屏至少完整看到 5 条。
8. 角色抽屉：该角色没有项目覆盖（来源是「跟随全局」）时，底部的「恢复跟随全局」置灰；有覆盖时照常可点。四项默认值卡片的「恢复跟随全局」**保持始终可点**：配置回包里没有逐项默认值的覆盖来源，数值与全局相同不等于没有覆盖（T-103 复核已给出反例），不得按数值相等置灰；这一处等内核给出来源后另行处理，不在本任务范围。
9. 备注正文用与文档页签相同的 Markdown 渲染组件显示。
