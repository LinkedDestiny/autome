### D1-P01 · 未启动会话的恢复输入丢失

- 主张：冷却 / 退避中等待启动的一轮，其 inject 只存在重试记录里，`Pause` / `Stop` 的 `advance` 会 `clear_retry`，
  恢复时 R3 只能读到更早一轮的输入。
- 设计位置：§3 R3、M-02。
- 裁决：**采纳**。
- 证据：`scheduler.rs` 的 `cooldown_route` 在 `Deferred` 时 `schedule_retry(.., inject, ..)` 后直接返回、没有会话；
  `advance` 对每次成功转换都 `clear_retry`（含 Pause / Stop）；`store.rs` `clear_retry` 删整条记录。反例成立。
- 修改落点：§3 新增 R3 的 inject 来源顺序——`advance` 在 `clear_retry` 前对 Pause / Stop 追加 `task.resume_input`
  事件；事件序号晚于 `latest` 的 `session.started` 才有效；其次才是 `latest` 的 inject。M-02 增 lib 测试 1 个与负向对照。
- 复提计数：0。

### D1-P02 · 停在 Retro 时手动复盘被当成原 Loop 会话

- 主张：手动复盘与 Loop 复盘节点同为 `Role { Retro }`，只比 kind 会让 R1 / R2 / §4 把手动轮当成原会话。
- 设计位置：§3、§4、§5、M-03。
- 裁决：**采纳**。
- 证据：`start_retro` 对 Paused / Stopped 开放且用 `Role { Retro }`；`reap_session` 现有特判是 `Retro && !Active`，
  设计原先又要把按 kind 的暂缓放在它前面，两者无法区分来源。反例成立。
- 修改落点：§5 引入来源标记事件 `session.manual_retro { session_id }`（`start_retro` 在会话起来后写）；`latest`、R1、
  §4 暂缓、旧特判都按标记判断；`task.resume` 在有运行中手动复盘轮时一律拒绝；旧特判保留 `!Active` 作为无标记老会话兜底。
  M-03 增调度测试 1 个（deferred 共 3 个）与负向对照。
- 复提计数：0。

### D1-P03 · 「停止已杀掉门禁」不成立，旧作业可能覆盖新结果

- 主张：停止只杀已有 `.pid` 的作业；刚 spawn、pid 未写的门禁逃过停止，之后写入与恢复重跑共用的路径。
- 设计位置：§2 `DiscardGateRuns`、M-01 / M-02。
- 裁决：**采纳**（前提确实错了）；修法取最小：先杀净再删，不改作业命名。
- 证据：`gate.rs` `start` 写 `.started` 后 spawn 即返回，pid 由 `WRAPPER` 第一句写；`stop_all` 只扫 `.pid`，
  源码注释自认刚启动的作业可能没有 pid；`Job::at` 以任务 / 节点 / sha 命名，重跑复用路径；`poll` 先读 `.exit`。
- 修改落点：§2 重写 `discard_node`：杀有 pid 的 → 对只有 `.started` 的最多等 3 秒 pid 出现后杀 → 杀完才删；明写残余窗口
  （包装脚本 3 秒内连第一句都没执行），与 `start` 已有的 clear-then-spawn 窗口同类，不在本任务消除。M-01 增 gate 单元
  测试 1 个与负向对照。不换成按运行隔离的作业身份：那会改 `run_gate` 全部查找路径，超出缺陷范围。
- 复提计数：0。

### D1-P04 · CLI `idle` 修改超出任务 §4 范围

- 主张：`autome-cli` 只许为显示文字而改，`idle` 是运行控制。
- 设计位置：§1、M-01。
- 裁决：**采纳**。
- 证据：任务 §4 原文；`main.rs` `idle` 在每次 tick 之后才判断，`Requeued` 留到该刻只在槽位被占时发生，占槽的运行会话与
  内核步骤本来就使其不空闲，只剩占槽者处于未到点冷却重试这一窄情形。
- 修改落点：§1 去掉 CLI 一行与「不算越界」的论证，改为不动 `autome-cli` 并写明后果；Backlog 新增 B-03，请用户决定是否
  授权这一处例外。M-01 的「五处」改「四处」。
