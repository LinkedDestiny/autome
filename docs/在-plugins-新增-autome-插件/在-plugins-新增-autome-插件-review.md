## 阻塞问题

### P01：固定 heredoc 在校验前已被解析，确认闸门可以被正文绕过

- **类别：违反任务目标。**
- **违反要求：**任务 §5 C2（任何创建命令之前必须完整展示并获得明确确认）、§3 A1（确认的完整正文应与传入 `--brief -` 的正文相同）。
- **设计位置：**第 4 步第 1 条（第 107 行）；第 5 步模板及其传输说明（第 123–133 行）；`check-card.sh` 第 6 项（第 162 行）。涉及 M-02 K11、M-03 T3 的输入方式。
- **根因：**设计先用固定 `<<'AUTOME_CARD_EOF'` 将未经检查的正文拼入 shell 命令，随后才要求 stdin 接收端拒绝正文中的同名独占行。shell 先识别结束行，校验脚本永远收不到被当作分隔符的那一行，无法执行设计规定的拒绝。
- **具体反例：**正文先放一份合格任务卡，再出现独占一行的 `AUTOME_CARD_EOF`，其后是一行 shell 命令。第 4 步尚未展示确认卡，shell 已把前半张卡交给校验器，并执行后面的正文行。即使最后因额外分隔符报错，也无法撤销已经执行的命令；后面的命令若为任务创建，便绕过 C2。
- **验证证据：**用 `/bin/sh`、`wc`、`printf` 做无真实创建的探针，接收端只收到截断前的 27 字节，随后输出 `PROBE: body tail executed as a shell command`；另一独立探针显示 `CHECKER_SEES_NO_DELIMITER` 后仍输出 `PAYLOAD_RAN_BEFORE_CONFIRMATION`。原始输出在 `.autome/output/review-1-adversarial-probe.log` 与 `.autome/output/review-1-security.log`。这些探针验证 shell 解析次序，未调用真实 `autome`。
- **检查范围：**第 4 步送检、第 5 步创建均使用同一固定分隔符，属于同一根因；仅对校验脚本直接喂含分隔符的 stdin，不能验证实际 shell 调用路径。
- **修改方向：**在正文进入 shell 解析前保证其按数据传输，例如先通过文件写入能力保存正文，再将同一文件分别重定向到校验命令和 `task new --brief -`；或在构造命令前选择正文中不存在的分隔符。同步调整两个调用点及对应契约，保留完整展示、确认与字节一致性要求。

### P02：排队结果无法按设计正确回显

- **类别：内部逻辑矛盾。**
- **违反条款：**设计「第 6 步 回显」要求读取真实 `task.state.state`、`started`、`queue_position`（第 135–138 行），却只允许输出“待开始／已开始”，并把排队位置放在“已开始”分支；「背景与现状」第 20 行还断言不带 `--draft` 时 `started: true`。关联任务 §3 A3（创建后回显）与 A6（真实命令行输出说明）。
- **源码证据：**`crates/automed/src/dispatch.rs:1497–1504` 在非 draft 创建后调用调度器，只有调度报告实际启动该 id 才令 `started=true`；同文件第 1548–1554 行仅在 `Queued / Requeued` 状态返回非空排队位置。现有测试 `create_without_the_new_params_is_unchanged`（第 4167–4174 行）明确断言槽位占满时 `state=queued`、`started=false`、`queue_position=1`。
- **具体反例：**项目并发为 1，已有一个任务占用槽位。用户确认“直接开始”后创建第二张卡，命令成功但任务进入排队。按现有两分支输出“已开始”会虚报运行状态；若按 `started=false` 输出“待开始”，又会附上只适用于 draft 的 `task start` 命令。非空排队位置也不应归入已经开始的分支。
- **根因与检查范围：**把“不带 `--draft`、进入调度”当作“已经开始执行”。已核对背景事实、第 6 步、README 字段说明和 M-03 V3：V3 的隔离空闲项目可以返回 `started=true`，但该结果不能推广到槽位已满的正常路径。
- **修改方向：**依据实际状态区分待开始、排队与已开始；排队时回显位置并说明等待执行，不附 `task start`。将背景事实改为“不带 draft 时进入调度，有空闲槽位并实际启动后才返回 `started=true`”，同步 README 对字段的说明。
- **验证边界：**本项依据源码与已有测试断言核对，未重跑该 Rust 测试，也未对真实账本创建任务。
