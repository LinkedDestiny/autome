# Bug 修复协议

定位 → 宿主复现检查 → 修复 → 修复门禁 → 独立复核 → rebase → 合并前门禁 → 等你合并 → 合并、验证 main、清理。
没有任务整理、设计、评审、裁决、批准设计或复盘。不要启动下一个会话，后续节点由 Autome 调度。

## Bug 文档

在任务目录写 `<slug>-bug.md`，不创建需求任务文件、设计文档、简报、retro.md 或 lessons.md。

<!-- kernel-contract: bug-status-block -->
```text
status: 已定位
fix-round: 0/3
复现命令: sh regression.sh
根因: 输入为空时错误地返回成功
复核: 待复核
```

五个必填键各写一次，放在第一个二级标题之前、代码围栏之外。冒号可用半角或全角。
`status` 只能是 `已定位`、`无法复现`、`不是 Bug`；`复核` 只能是 `待复核`、`通过`、`打回`。
`fix-round` 是非负整数 `k/N`，以 Autome 预算行和账本为准，不自己计算预算。
`已定位` 时复现命令和根因必须非空且不是 `无`，其它状态可写 `无`。复现命令只能一行。
工作区项目额外写可选键 `repos: 仓库A, 仓库B`，已定位时必须点名实际成员；后续只可追加，不可删除。
<!-- /kernel-contract -->

正文依次用「现象」「复现」「根因分析」「修复说明」「复核意见」五个二级标题。
定位轮写前三节、`fix-round: 0/N` 和 `复核: 待复核`；信息不足时写 `无法复现` 并列出缺少的环境、步骤、期望与实际。
符合现有设计而要求改变行为时写 `不是 Bug`。这两种状态会等待用户补充或决定；不要自行新建需求任务。
如有 `<slug>-replies.md`，先完整读取用户补充信息。

## 复现与修复

定位轮提交能抓住问题的回归测试，不修产品代码。复现命令应稳定、不依赖网络与时序；
宿主在 worktree 根目录以 `sh -c` 执行。工作区项目的工作目录是工作区目录，命令自己 `cd <成员>`。
修复前必须失败、修复后必须通过。超时、命令不存在或不可执行不算成功复现。
首次未复现退回定位并带失败原因和日志；连续两次未复现等待用户信息。

修复轮做最小改动，不改回归测试，不扩大无关范围。只改变空白、换行、行尾逗号且不改变语义的格式化不算修改回归测试，门禁要求时修复轮应当做；字面量内部的空白不在例外内。断言、输入、用例名、跳过标记一律不得改。保持 `status: 已定位` 和原复现命令，
可修正根因，按预算行更新 `fix-round`，每次必须重置 `复核: 待复核`，填写修复说明。
宿主执行复现命令及配置的项目门禁，任一失败退回修复；项目 `[gate] run = "before_merge"` 时修复门禁只跑复现命令，同时配了 `[gate] quick` 时跑复现命令和快检；项目完整门禁留到合并前门禁。预算耗尽由 Autome 停下，用户可追加轮次。

## 回归测试本身有缺陷

产品修好后，若测试仍因夹具错误、断言与契约不符或格式门禁之外的测试自身问题失败，修复轮或复核轮可以声明回归测试有缺陷。必须给出证据，不能把产品尚未修好当成测试缺陷；纯格式问题仍按格式化例外处理。

在 Bug 文档头部另加可选键 `回归测试: 有缺陷`（唯一合法取值；没有声明时不写此键），保持 `status: 已定位`、复现命令和预算行规定的 `fix-round`。修复轮保持 `复核: 待复核`，复核轮写 `复核: 打回`。另写固定二级标题 `## 回归测试缺陷`，列出四个非空列表项：

- 用例：有缺陷的测试路径与用例名。
- 缺陷：夹具或断言哪里违反了产品契约。
- 证据：产品修复后测试卡在哪一步，给出命令、实际结果与契约依据。
- 建议：应如何修正测试，保留怎样的回归约束。

声明的这一轮不得修改、删除、跳过或弱化回归测试。内核会退回定位轮修正，任务内最多 2 次，不增加修复轮次；超限交由用户处理。

定位 prompt 带「修正回归测试」一节时，只能修改回归测试与任务文档，不得修改已有产品修复；按该节边界处理，结束时删除头部 `回归测试: 有缺陷`，写 `status: 已定位` 和 `复核: 待复核`。宿主用修正后的测试分别检查基线与 HEAD：基线失败且 HEAD 通过才接受并进入修复门禁与复核；基线失败但 HEAD 仍失败则回修复轮；基线未复现按原未复现规则处理。复核时须核对缺陷说明与实际测试改动一致，并确认没有弱化断言。

## 独立复核

复核使用与修复不同的模型。独立检查：根因是否站得住、回归测试是否有意义、改动范围是否最小。
检查定位提交到修复提交的差异，拒绝删除、跳过或弱化回归测试的修复。
保持状态、轮次、复现命令、根因与 repos 不变；写 `复核: 通过` 或 `复核: 打回`，在复核意见中说明证据。
打回返回修复并计一轮；通过进入合并流程。不要自己合并。

## 会话边界

只在当前 worktree 内工作，不切换分支、不推送远端、不改 `.autome/` 配置。
超过 5 行的原始输出放 `.autome/output/`。本轮改动用 git add 和 git commit 提交；权限拒绝时保留改动，记录由 Autome 兜底。
完成本轮就结束会话。
