### 逐条裁决

**D1-P01**（对应 R1-01）
- 主张：任务合并后其全部历史 `passes`（含早期伪脚本自报的键）被提升为跨任务可信记录，B-S3 不成立。
- 设计位置：B.3 快照来源、信任边界第 4 条；M-03 `gate_report` ③。
- 裁决：**采纳。**
- 理由：合并只担保最终那份脚本，不担保早期脚本及其声明的键；反例成立。检查范围：本任务记录、跨任务快照、失败/超时的部分报告、快检报告。
- 修改落点：B.3 把来源拆成两类——本任务自己的门禁（全部 `passes`，只供本任务）与已合并任务「合并所依据的那一次门禁」（最后一条 `ok=true`、非快检、`sha` 等于合并时分支末端的 `gate.result`，对不上则不发布）；信任边界第 4 条改写并给出「伪键 K → 恢复脚本 → 真实通过 K0 → 合并」的判别对照；M-03 `gate_report` 5→6 个，③ 改过滤口径、新增 ⑥ 判别对照，负向对照补「发布全部历史 `passes`」；风险表同步。
- 复提计数：0。

**D1-P02**（对应 R1-02）
- 主张：键与 `Build core` 没有约束实际被测的内核二进制；`AUTOMED_BIN`/`AUTOME_BIN`、`CARGO_TARGET_DIR`/`CARGO_BUILD_TARGET` 可让「键相同、测的是另一份二进制」。
- 设计位置：B.2 工具链指纹、B.4。
- 裁决：**采纳。**
- 理由：违反 B-S4 / X-3；覆盖变量只是路径字符串，纳入键也防不住同一路径被换成旧二进制，所以采用「清除」而不是「纳入键」。检查范围：`apps/web/test`、`apps/web/server/core` 全部读取点；Desktop 测试自己删除并恢复该变量，不构成隔离。
- 修改落点：B.2 指纹去掉 `CARGO_BUILD_TARGET CARGO_TARGET_DIR`，新增条款——引擎启动即 `unset AUTOMED_BIN AUTOME_BIN CARGO_BUILD_TARGET CARGO_TARGET_DIR`（所有模式），原本有值就在日志写明；B.4 补产物位置恒为 `target/debug`；M-02 新增用例 ⑫（ci-reuse 11→12 个）及负向对照；风险表同步。
- 复提计数：0。

**D1-P03**（对应 R1-03）
- 主张：`autome-cli` 只有 bin 目标，`cargo test -p autome-cli --lib` 退出 101，快检候选不可执行。
- 设计位置：C.2 候选表优先级 2、3；M-04。
- 裁决：**采纳。**
- 理由：Cargo.toml 与源码布局直接证实。检查范围：三个 workspace crate 与两条生成规则（改动所在 crate、domain 的依赖者）。
- 修改落点：C.2 候选表按 `cargo metadata --no-deps` 的 target 类型选 `--lib` / `--bins`（`automed`、`autome-domain` 用 lib，`autome-cli` 用 `--bins`）；M-04 新增用例 ⑩（8→10 个，含 ⑨），要求真实 `--no-run` 退出 0，并加负向对照。
- 复提计数：0。

**D1-P04**（对应 R1-04）
- 主张：`npm exec --prefix apps/web -- vitest related` 在仓库根执行，不加载 `apps/web/vitest.config.ts`，丢失串行与 60 s 超时，D 之后也不加载 project 分组与 `globalSetup`。
- 设计位置：C.2 候选表 Web 一行；M-04 用例 ③。
- 裁决：**采纳。**
- 理由：`--prefix` 只改依赖查找位置，实测 cwd 仍是仓库根；默认配置下 `testTimeout=5000`。检查范围：C.2 Web 候选、M-04 ③、M-06 命令（后者用 `cd`/`npm run`，无此问题）。
- 修改落点：C.2 改为 `cd apps/web && npx vitest related --run <去前缀路径>`，写明与完整 Web 测试同一份配置；M-04 用例 ③ 改命令文字，新增 ⑨（在候选的 cwd 下用 `resolveConfig` 断言有效配置），负向对照补「改回 `npm exec --prefix`」。
- 复提计数：0。

**D1-P05**（对应 R1-05）
- 主张：汇总以字符数限定，而 `gate::tail` 按字节截，汉字名可使用例块被裁掉，M-01 契约 ③ 不成立。
- 设计位置：A.3 第 3 条用例块；M-01 用例 ③。
- 裁决：**采纳。**
- 理由：反例的字节数已复算（472 字节/行，18 行 8496 字节）。检查范围：Rust 与 Vitest 共用的汇总块、复用它的快检失败摘要。
- 修改落点：A.3 改为整个汇总尾部 ≤ 3000 字节、用例块 ≤ 2400 字节，每行先截 160 字符再截 200 字节且落在字符边界，「另有 N 个」的 N 是未列出的真实数；M-01 `ci-summary` 6→7 个，新增 ⑦ 多字节用例（含经 `gate::tail` 同算法取尾），负向对照补「按字符截断」。
- 复提计数：0。

**D1-P06**（对应 R1-06）
- 主张：设计把 V-5「空闲机器」硬指标替换成带负载交替基准，可能在没满足用户目标时关闭 M-06。
- 设计位置：基线口径、D.2、M-06 契约。
- 裁决：**采纳。**
- 理由：任务文件 V-5 / D-R2 / D-V1 明写空闲机器；改验收条件不是设计轮的权限。保留的现实约束（主机常年有 Loop 在跑）改为「取数方法」而不是「降低标准」。
- 修改落点：D.2 重写——空闲口径（1 分钟 load average ≤ 2 且无其它构建/测试进程，最长等 30 分钟，前后各 3 次交替，中位数 ≤ 50%）为硬指标，负载口径仅作补充、不得用来声明 V-5 通过；取不到空闲数据时如实记录并转人工验收清单 H-01（新增）；基线口径、M-06 契约与负向对照同步。
