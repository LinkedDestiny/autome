# M-03 · 实现 #3 · 待审

## 实现与范围

- 作业目录增加 `.passes`、`.report`；在 clear 后、启动命令前落快照，导出 `AUTOME_GATE_PASSES` / `AUTOME_GATE_REPORT`。clear、discard_stale、discard_node 一并清理。
- Store 从同项目事件取最近 7 天通过记录，按时间/事件序号倒序，最多 5000 条。本任务保留失败/快检中的已通过步骤；其它任务必须已合并，只选最后一次通过且非 quick 的门禁，再核验 sha 等于合并提交第二父提交。无法解析合并末端不发布。
- 报告上限 256 KiB，缺失、读失败、格式错误不加字段；五种状态全覆盖。steps.ran 是实际执行数（含 failed、partial），只有报告状态 ran 进入 passes。沿用未命中快照则计 unverified。
- 时间线显示执行/沿用、非零未跑/未核实数，未核实使用现有错误色；旧事件摘要与整次沿用不变。同步 technical-design §8.1。
- gate_queue 与 end_to_end 中已有的 Job 字面量补两个字段，不改变队列行为。未修改配置、协议、门禁时机或 M-04–M-06。

### 2. 失败分支

- 读盘失败：report 路径为目录与不存在，read_report 返回 None；格式错误/未知版本/未知状态/缺字段/额外 Tab/空名/非法键/超限均忽略。无报告真实内核确认事件无新字段。
- 失败与超时：counts 用例实际启动命令分别 exit 0、exit 7、写完报告后 sleep 并触发超时 124，三者已完成步骤报告均保留；相关 lifecycle 检查超时终止与日志保留，通过。
- 空输入：空文件拒绝，只有合法头的空报告接受并产生空 passes、零计数，通过。
- 拒绝授权、外部服务不可达：不适用；本里程碑没有授权入口或外部服务调用。未核实沿用作为可疑输入单独验证，不提升为通过记录。

### 3. 全部迁移

- 作业：启动→Running→Done(0)、Done(7)、Done(124)，报告读取均验证；进程/退出标记消失→Vanished、clear 后重启、discard 等待 wrapper 后清理，由 17 例 lifecycle 验证。
- 报告：五种状态→各自计数；仅 ran→passes；reused 分快照命中/不命中两支，后者额外 unverified；无效/缺失→旧事件字段，逐项通过。
- 信任：未合并→不对外发布，合并且最终 sha 匹配→只发布最终 ran，sha 不符/解析失败→不发布；同任务→全部历史 passes（仍受年龄/数量限制），Store 用例通过。
- 时间线：无报告旧摘要、有报告零/非零步数、未核实提示、整次沿用独立措辞，12 例通过。

### 4. 输入域边界

- 报告 256 KiB 恰好接受、+1 字节拒绝；空文件/仅头、单步骤报告均覆盖。
- 脚本现有哈希键域 40–64 位小写十六进制：40/64 接受，0/39/65、非法字符拒绝；快照 0/1/5001 条及 7 天截止两侧覆盖。
- 时间线零步、全沿用、非零未跑/未核实覆盖。闰日、跨年、数字前导零不适用：此协议不解析日历输入或十进制编号，键按原文处理。
