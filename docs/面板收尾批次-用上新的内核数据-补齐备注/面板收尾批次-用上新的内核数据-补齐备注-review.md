## 可要求再评审的问题

### R2-P01 · 时间线窗口与文档／标签导航互相覆盖查询参数

- **类别：** 内部逻辑矛盾、违反任务目标。
- **追溯：** 任务 **C-2、验-3、§6 约束 10**；设计 **C-Q1** 的「URL 状态，刷新保持」与「此后的重验都带 from」、**C-Q3 第 268–272 行**的「已展开日志所在会话在整个页面生命周期里留在渲染树中」；**M-05 验收契约**的窗口固定与 W7 不回归。
- **设计与代码证据：** C-Q1 明确规定挂载后调用 `setSearchParams({from: window.from}, {replace: true, preventScrollReset: true})`。对象写法设置的是新查询串，不会自动合并旧查询参数；`replace` 只控制历史记录。项目锁定 React Router **8.5.1**，其[官方 useSearchParams 文档](https://reactrouter.com/api/hooks/useSearchParams)列出了对象写法与基于现有参数的回调写法。现有 `apps/web/app/components/task-detail-data.ts:51` 从 `doc` 选择正文，缺失时回到任务卡；`task-changes-model.ts:9` 从 `tab` 选择标签。反方向上，`task-docs-model.ts:4` 产生 `?doc=…`，`task-docs.tsx:7` 再拼接 `tab=docs`，这些链接完全不保留 `from`。主标签导航 `apps/web/app/routes/tasks.$id.tsx:34` 已采用复制当前查询参数的方式，可沿用。
- **具体反例 1（挂载覆盖已有选择）：** 直接打开 `/tasks/T-1?tab=docs&doc=design.md`，SSR 先显示设计正文；窗口固定调用把 URL 改为 `?from=S-41`，触发导航后 `doc` 消失，loader 改读任务卡。非合并段任务的 `?tab=changes` 同样会在挂载后回到默认文档标签。这不是缺少测试，而是指定的参数替换方式直接改变用户选择。
- **具体反例 2（文档导航解除窗口固定）：** 用户打开最近 20 个会话（41–60），窗口固定为 `from=S-41`，展开会话 41 日志；新会话 61 到来后按设计保留 41–61。随后点击任一文档链接，现有链接跳到 `?doc=…&tab=docs`，把 `from` 清掉；该次 loader 恢复缺省最近 20 个窗口（42–61），会话 41 及已展开日志被移出渲染树。即使 effect 在这之后再次固定，也只能固定新的窗口，无法挽回已卸载的日志状态。
- **根因与同类检查范围：** 新增 `from`／`timeline` 与既有 `tab`／`doc` 共用查询串，但方案没有保持它们相互独立。已检查窗口初始化、主标签链接、任务卡／正文／证据链接，以及「显示更早」链接；设计中的直接 `?timeline=all` 也会丢掉当前文档与标签选择，应归入同一修正。主标签链接现有复制参数的方式没有这项覆盖问题。
- **建议修改落点：** C-Q1、C-Q3 与 M-05：所有上述导航都从当前 `URLSearchParams` 的副本出发，仅设置／删除自己负责的键；窗口初始化只在未指定 `from` 且未要求 `timeline=all` 时补 `from`；文档导航保留窗口参数，「显示更早」保留标签与文档参数并有意切换窗口模式。沿用 M-05 的浏览器链路加入「已追加新会话后再切换文档」这一步，核对最早已展开日志仍在；直接打开文档链接应在挂载后保持原正文。无需改变用户要求的 A–F 范围或窗口固定方向。
- **验证边界：** Node URL 实验及真实 `docsView` 输出已确认：`?tab=docs&doc=design.md` 经对象替换只剩 `?from=S-41`；现有文档链接解析后 `from` 缺失。原始结果在 `.autome/output/review-2-static.txt`。没有安装依赖或运行浏览器，未把这个静态反例表述为 React 挂载实测；曾尝试直接导入完整标签模型，因其传递依赖含 `.tsx`、Node 原生加载不支持而未执行，随后缩小为 URL 与可直接加载的文档模型验证。
