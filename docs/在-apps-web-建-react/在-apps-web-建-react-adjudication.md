### D1-P01（评审编号 D4-P01）Node 下限被设计抬到 22.18.0

- 主张摘要：任务 R-02 与硬性约束 5 规定下限 22，设计 §2/§3/§4/风险/M-02 把下限定为 22.18.0，并让 22.0–22.17 被拒绝，缩窄了任务要求的兼容范围。
- 设计位置：§2 `engines`、§3 原生类型剥离、§4、风险安排、M-02 契约。
- 裁决：**采纳**。
- 证据：任务 R-02「Node ≥ 22」、硬性约束 5「下限 22」，设计无权自行抬高。核对 `npm view`：`vite@6.4.6`、`vitest@3.2.7` 的 engines 含 `>=22.0.0`，`eslint@9.39.5` 为 `>=21.1.0`，`tsx@4.23.15` `>=18`，`@react-router/*@7.18.5` `>=20`，`express@5` `>=18`；`@react-router/dev@7.18.5` 的 vite peer 含 `^6`，`typescript-eslint@8.72` 的 eslint peer 含 `^9`。用该组合在空包上做 `npm install --dry-run`，无 ERESOLVE（315 个包）。
- 修改落点：
  - §2：vite^6、vitest^3、eslint^9、@eslint/js^9，新增运行时依赖 tsx^4，禁止 vite7+/vitest4+/eslint10+；`engines.node` 改 `>=22.0.0`；背景里的引擎事实改写。
  - §3：服务端 TS 由 tsx（`tsImport`）执行，不再依赖原生类型剥离，去掉 `erasableSyntaxOnly`。
  - §4：`MIN_NODE_VERSION = '22.0.0'`，提示语改为「22 或更高版本」，删除抬高下限的理由段，注明 22.0 无法实测的取证口径。
  - §7：`probe:sqlite` 改用 `tsx` 运行；补充 `node:sqlite` 在 22.13 以下的限制。
  - 风险安排：22.18 条目换成「22 线可运行性」，规定不兼容时换依赖版本、不得抬高下限。
  - M-02 契约：用例改为 9.9.0 ✗、21.7.3 ✗、22.0.0 ✓、22.9.0 ✓、22.23.1 ✓、26.5.0 ✓、`abc` ✗（仍 7 个）；伪造版本启动改为 21.7.3 与 9.9.0（仍 2 个）；结构用例核对 `MIN_NODE_VERSION` 为 `22.0.0`；负向对照改为字符串比较会放行 `9.9.0`。用例总数不变（11/23）。
- 复提计数：0。
