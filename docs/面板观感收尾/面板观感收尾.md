## 目标与非目标

**目标。** 覆盖 A-1…E-4 全部 24 条要求。先修两个共同根因：`.seg` 两种形态、表单控件的元素级基础样式。再按页收紧密度，修 E-4。每条要求至少有一条不依赖浏览器的 vitest 断言。需要浏览器才能判的（一屏可见、裁切、行高实测）写进 e2e 布局用例，由宿主门禁执行，审计轮能跑时也跑。

**非目标。**

- 不改信息结构、路由和入口；不加页面。
- 不改颜色令牌和共用组件类名（`.seg`、`.pill`、`.chk`、`.inp`…）。只新增一个共用组件 `ui/drawer.tsx`，类名 `.drawer*`。
- 不做深色主题、窄屏适配。
- 不改内核和协议。E-4 只改 `apps/web/server/`。
- 不在本任务分支上重拍 README 五图（见方案「总-Q4」）。
- 草稿跳转确认与抽屉焦点管理已按用户决定纳入 M-12、M-13；不扩展到其它导航或弹窗。

### A-Q2 表单控件基础样式

- **挂在元素选择器上，用 `:where()` 把特异性压到 0。** 选择器是 `:where(input:not([type=checkbox],[type=radio],[type=hidden],[type=file],[type=range]), select, textarea)`。任何页面的类规则都能覆盖它，没写页面规则的控件自动得到动森外观。基础外观与 `.inp` 一致：38px 高（`textarea` 不限高）、`0 14px` 内边距、`--animal-radius-sm`、`--animal-bg-input` 底、2px `--animal-border-light` 边、`--ui-shadow-input` 内阴影、`600 13px var(--animal-font)`、`--animal-text` 字色；禁用态与 `.inp:disabled` 一致。`.inp` 保留，作为显式写法。
- **下拉框。** `appearance: none`，右侧 36px 内边距。箭头用两段 `linear-gradient`（`transparent` 加 `var(--animal-text-muted)`）画成 V 形，不用 SVG。
- **复选框与单选框。** `:where(input[type=checkbox], input[type=radio])`：`appearance: none`，18px，2px `--animal-border` 边，`--ui-white` 底。复选框圆角 `--animal-radius-sm`，单选框 `50%`。选中时底和边都是 `--animal-primary`。复选框的勾用 `::after` 画：一个旋转 45° 的 L 形边框，颜色 `--ui-white`。单选框用 `box-shadow: inset 0 0 0 4px var(--ui-white)` 画中心点。`.seg input`、`.switch input`（0,1,1）仍把原生控件藏起来，特异性高于 0，不受影响。
- **`fieldset` / `legend`。** `fieldset` 是 2px `--animal-border-light` 边、`--animal-radius`、`12px 14px` 内边距、`margin: 0`、`min-width: 0`。`legend` 是 `0 6px` 内边距、12px / 800、`--animal-text-muted`。现有 `.task-new fieldset { border: 0 }` 这类页面规则照常覆盖。
- **聚焦。** `:where(input, select, textarea):focus-visible` 用 3px `--animal-focus-yellow` 描边，满足焦点环守卫。
- **`type=hidden` / `type=file`。** 不在选择器里。唯一的 `type=file` 已经 `visually-hidden`，由外层 `label.btn` 承担外观。
- **页面规则的清理。** 页面规则只保留布局声明（宽、高、flex）。重复声明边框、底色、圆角、字体的删掉，让外观统一来自基础规则：`.add-project input…, .add-project select`、`.palette input` 的边框与圆角、`.onboarding-editor textarea`、`.task-new textarea` 的边框。有意保留的专用外观只有 `.stepper input`（透明，嵌在步进器里）。

### A-Q3 验-7「全站检索」的写法

验-7 做成会话能跑的三条断言，放在 `test/ui-base.test.ts`（M-02）：

1. **CSS 层。** 解析 `app.css`，找到上面三组 `:where` 基础规则，断言它们覆盖 `input`、`select`、`textarea`、`fieldset`、`legend`、`checkbox`、`radio` 七类，并带 `appearance: none`、圆角令牌和黄色焦点环。
2. **源码层。** 扫 `app/**/*.tsx` 里每一处 `<input`、`<select`、`<textarea`、`<fieldset`。`input` 的 `type` 必须是 text、search、number、checkbox、radio、hidden、file 之一，且 file 必须带 `visually-hidden`。也就是说，出现新类型时测试会提醒补基础样式。
3. **反向层。** `app.css` 里不得出现 `appearance:` 取 `none` 以外的值，也不得出现 `all: revert / unset / initial`。这两种写法才会把原生外观放回来。

  - `open`：只保留 `present` 中存在、且当前 `waitingKind(task.state)` 非空的任务。这同时挡住「已移除项目停在 `failed`」和停在 `await_design_approval / await_merge / await_info / not_a_bug` 的四种 `active`：任务不在列表里就不计；事件流与当前状态不一致时，也以当前状态为准。
  - `closed` 区间加上 `task` 字段，只累计 `present` 中的任务。`ended` 同样只数在列表里的任务。
  - `waiting` 映射按同一规则过滤。
- **移除与重新添加。** 累计状态不删，过滤在每次调用时做。任务被移除后，它今天的等待从总数里消失；项目重新添加、任务回到列表后又计入。
- **依赖。** 只用 `lib/waiting.ts` 的 `waitingKind`，它已在 `stage-panel.ts` 的暂存清单里，不新增 `server → app/lib` 导入（教训 L-05）。
- **显示。**
  - 总数为 0 时数字写「0 分」（不是 `formatSpan(0)` 的「0 秒」），附注「今天没有等待」。
  - 有进行中的等待、但今天还没有结束的：附注「正在等你，今天暂无结束的等待」。
  - 有结束的：沿用 `endedWaiting`。
  - 新文案放在 `lib/overview-labels.ts`。

- **R-4 看板裁切的成因要靠浏览器确认。** M-10 先加 `flex: 1 1 0`，再用「已取消展开」的新断言判定。门禁失败时按 E-Q3 沿父链补齐。
