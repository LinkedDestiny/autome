# 面板观感收尾：把已上线的页面对齐已确认原型的密度与控件样式

## 背景

T-101（提交 `4f9d74b2`）按动森风格重做了 Web 面板，功能齐全：总览、项目看板、任务详情、Loop 配置（全局 / 项目、六个角色、四项默认值）、技能绑定、环境页都能用。但 2026-11-18 在真实账本（71 个已完成任务、126 个技能）上逐页截图对照用户已确认的原型 `docs/design/autome-web-panel-v3.html`，有一批观感没做到原型水平。截图见附件（1512×944）。

这些问题有两个共同根因，修的时候先修根因，不要逐页打补丁：

1. **分段选择只认一种写法。** `apps/web/app/styles/app.css` 里 `.seg` 的样式只覆盖 `label > input[type=radio] + span`。Loop 配置页的范围切换和「Loop 配置 / 项目信息」标签用的是 `.seg` 里放链接，结果是一排没有间隔、看不出选中项的文字。
2. **表单控件没有全站基础样式。** 输入框、下拉框、搜索框、复选框、`fieldset` 只有在个别页面单独写了样式的地方才是动森观感，其余露出浏览器原生外观（技能页的项目下拉与搜索框、角色抽屉的模型输入框、技能抽屉的复选框与 `fieldset` 边框、移除项目的确认输入框）。

T-101 的复盘（`docs/web-面板按动森风格重做/lessons.md` L-01、L-04）还指出：实现轮的沙箱里不能执行 `ps`、不能监听端口，浏览器用例和截图在实现轮跑不起来。所以本任务的验收尽量写成不依赖浏览器也能判的断言（见「约束」）。

## 要做什么

一次设计、一次评审，按下面分组里程碑实现。只改 `apps/web`，不改内核。

### A 全站基础

- A-1 分段选择支持两种内容：单选框（现有）与链接 / 按钮；选中项有白底与阴影，未选中项之间有间隔。范围切换、页内标签、筛选都用它。
- A-2 表单控件的全站基础样式：文本输入框、搜索框、下拉框、多行文本、复选框、单选框、`fieldset` / `legend`。圆角不小于 12px，用现有令牌，聚焦用现有的黄色描边。之后任何页面不单独写也不会露出原生外观。
- A-3 丝带标题只保留两档字号（页面标题一档、区块标题一档）。现在「新建任务卡」「添加项目」「环境检查」三页的丝带字号约为其它页的两倍；「添加项目」页的丝带还被拉成了通栏色条。
- A-4 抽屉的统一骨架：标题行右侧一个小的关闭按钮（图标或「关闭」），内容区内部滚动，底部固定操作区。现在角色抽屉顶上是一个通栏的大「关闭」按钮，技能抽屉的「来源」被挤到屏幕外。

### B Loop 配置

- B-1 范围切换显示成分段选择，当前范围高亮；项目范围下第二行的「Loop 配置 / 项目信息」同样。
- B-2 角色卡收紧到原型的密度：1512×944 下，设计循环、实现循环两排角色卡加四项默认值在不滚动的情况下全部可见（现在每张卡约 290px 高，默认值在屏幕外）。模型名与 effort 胶囊同一行不换行（现在「审计」卡的 medium 掉到了下一行）。
- B-3 角色卡要看得出可以点开编辑（悬停态与一个「编辑」提示），现在整张卡是按钮但没有任何提示。
- B-4 角色抽屉：模型输入框用 A-2 的样式；「绑定的技能」列出已绑定技能的名称，没有时写「还没有绑定技能」；「添加技能」是一个明确的次级按钮，跳到技能页并带上当前范围。
- B-5 四项默认值：四张卡同一种布局（现在第一张的标签和步进器在同一行，其余三张分两行）；保存按钮统一叫「保存」，值没改时不显示或置灰；保存后的结果提示就地出现。
- B-6 「项目信息」标签页：三个区块在页面内部滚动，不被裁切（现在「配置（只读）」只露出一行，「移除项目」的输入框被页面底边切掉一半）。

### C 技能

- C-1 技能卡固定高度：描述最多三行，超出省略；路径一行，超出从中间或末尾省略。1512×944 下一屏至少能看到 9 张卡（现在 3 张）。完整描述放进抽屉。
- C-2 顶部的项目选择与搜索框用 A-2 的样式；项目选择用分段选择或与 Loop 配置页一致的范围切换。
- C-3 卡片上的绑定状态用胶囊表达：未绑定是描边胶囊，已绑定写出角色名（如「审计 · 复盘」）的实心胶囊。
- C-4 技能抽屉：角色勾选用 A-2 的勾选块；看不到该技能的角色整行置灰并在同一行内说明原因；「保存绑定」固定在底部；「来源」可见。

### D 任务详情

- D-1 时间线改成紧凑行：每行一条（时间、图标或角色、一句话、右侧耗时 / 花费 / 结果胶囊），行高不超过 44px，会话行可展开。1512×944 下时间线区域至少同时看到 10 行（现在 4 行，每条系统事件占一张大卡片）。
- D-2 「显示更早的 N 个会话」做成按钮样式。
- D-3 没有可用操作时不渲染操作区（现在已完成任务的标题右侧有一个空的圆角框）。
- D-4 里程碑条：全部里程碑在一行内可横向滚动，或折成「13 / 13 已完成」加可展开的列表；不能只露出前两个而没有任何还有更多的提示。
- D-5 右侧文档标签页里的文档胶囊不被裁切（现在下半截被盖住），「证据（38）」的展开入口与胶囊同一种样式。
- D-6 阶段条里「评审·裁决」一格的文字「$0.65 + 1 个无计费」不换行溢出。

### E 其余页面

- E-1 环境页：工具已安装且已登录时只显示一行（名称、路径、状态、版本），安装与登录说明收进「查看安装方法」的展开区；未安装或未登录时才直接展开。
- E-2 添加项目页：目录候选列表占满卡片可用高度并内部滚动（现在只露出三行半，页面下方大片空白）。
- E-3 项目看板：「已完成」列的内部滚动区延伸到底，底部的「已取消」分组不被页面底边裁掉。
- E-4 总览「等你的时间」算错了（这条是缺陷，不只是观感）。2026-11-18 04:52「等你处理」为 0，数字块却显示「4 时 52 分 · 今天暂无结束的等待」，正好是当天已过去的时长。原因：`apps/web/server/overview-summary.ts` 从 `events.since` 累计所有任务的等待区间，不看任务是否还在面板里。真实账本里 T-7 属于 2026-10-11 已移除的项目，最后一条 `task.updated` 停在 `failed`，于是被当成一直在等用户，每天从零点计到现在。修法：只统计当前任务列表里存在的任务（已移除项目的任务不计），并补一条用例：已移除项目里停在 `failed` 的任务不计入等待时间。今天确实没有等待时数字显示「0 分」并写「今天没有等待」。

## 不做什么

- 不改信息结构、不加新页面、不动内核与协议。
- 不改 T-101 已定的颜色令牌与组件命名；需要新令牌时沿用 `--ui-` 前缀。
- 不做深色主题，不做窄屏适配。
- 不重拍 README 截图以外的文档。

## 约束

- 硬规则不变：全中文（专有名词除外）、1512×944 下不出现整页纵向滚动、圆角不小于 12px、不用纯黑、立体阴影只用于主按钮。
- Host / Origin 鉴权、任务详情 150 KB 的服务端渲染上限测试、现有 e2e 用例数不减少。
- 改掉任何已有的用户可见文案、类名或结构时，同一轮把 `apps/web/test` 与 `apps/web/e2e` 里期待旧值的断言一起改完，并在证据里写出检索命令与命中数（T-101 教训 L-03）。
- 验收断言优先写成不需要浏览器的形式：对服务端渲染出的 HTML 与样式表做断言（例如「`.seg` 内的链接有选中态规则」「技能卡描述带行数限制的类」「没有操作时不输出操作区节点」）。必须用浏览器才能判的（一屏可见行数、是否裁切）写进 e2e 的布局用例，由宿主门禁与审计轮执行。
- 截图脚本与布局用例在判定前断言页面可见文本不含字面量 `undefined`、`NaN`、`null`、`[object Object]`（T-101 教训 L-02）。

## 验收标准

- 验-1 Loop 配置页：范围切换与页内标签有可见的选中态；1512×944 下两排角色卡与四项默认值无需滚动全部可见；六张角色卡的模型与 effort 都在同一行。
- 验-2 角色抽屉与技能抽屉：没有任何浏览器原生外观的控件；关闭按钮在标题行；底部操作区始终可见。
- 验-3 技能页：真实 126 个技能下一屏至少 9 张卡，卡片等高；最长描述（`agent-browser`）被截到三行。
- 验-4 任务详情：T-101 这样 44 个会话的任务，时间线区域一屏至少 10 行；已完成任务没有空的操作框；文档胶囊完整可见；13 个里程碑都能看到或有明确的展开入口。
- 验-5 环境页：四个工具都正常时，整页不需要内部滚动就能看完。
- 验-5b 总览：真实账本上没有任务等用户时，「等你的时间」不随当天时间增长；已移除项目的失败任务不计入。
- 验-6 添加项目页、新建任务页、环境页的丝带与总览页同一档字号；添加项目页没有通栏色条。
- 验-7 全站检索：除被 A-2 基础样式覆盖的控件外，页面里不存在未带样式的 `select`、`input`、`textarea`、`fieldset`；布局巡检用例覆盖本卡提到的每个页面与两个抽屉。
- 验-8 `sh scripts/ci-local.sh` 通过；e2e 用例数不少于合并前。
- 验-9 人工验收清单里给出每个页面改前改后的对照截图路径，用户看图确认。
