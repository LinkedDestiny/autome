## 现象
T-33 的复核轮（会话 ses-f3ecc801146e4840b901f947bd5807d6）用 `glob.glob('docs/*/*-bug.md')[0]` 定位 Bug 文档，选中了已合并到 main 的 T-30 文档 `docs/内核提交会删除大量文件时不拦截/…-bug.md`，把「复核第 2/3 轮：通过」写进了那份文件并提交（T-33 分支提交 `3ba0cec`）。本任务自己的 `复核:` 字段仍是 `待复核`，内核报「协议失败：复核 字段不符合当前轮次」。真正的错误（改了别的任务的文档）没有被指出，T-33 分支还带着对 T-30 文档的改动，合并后会污染 main 上 T-30 的文档。
## 复现步骤
1. 仓库里有另一个任务的 `docs/<other>/<other>-bug.md`（已合并）。
2. 让 Bug 任务的复核轮只修改那份文档并提交，本任务文档不动。
3. 会话结束 → 报「复核 字段不符合当前轮次」，而不是指出改错了文件。
## 期望行为
- 复核轮（Bug `fix_review`）和需求的审计轮、复盘轮是「只写本任务文档」的轮次：会话结束时内核检查本轮提交相对会话开始的 diff，若改动了本任务文档目录之外的任何文件（含其它任务的 `docs/<slug>/`），判协议失败，原因写明「复核轮只能修改 docs/<slug>/ 下的文件，本轮改了：<路径列表>」。已有的 `audit_edited_the_design` 守卫是同类思路，可复用其结构。
- 定位轮与修复轮不受此限制（它们要改代码）。
- 本任务文档的 `复核:` 字段仍为 `待复核` 时，错误文案补一句「本轮没有更新 docs/<slug>/<slug>-bug.md」，并给出该文件的精确路径。
- e2e：复核轮改了另一任务的文档 → 协议失败且原因含该路径；只改本任务文档 → 照常。
