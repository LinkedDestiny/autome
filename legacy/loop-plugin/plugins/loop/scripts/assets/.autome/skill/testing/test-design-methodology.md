# 测试设计方法论

本文档回答「测试用例从哪里来」。完成纪律（门禁集合）中判定型条目的强度依据即来自这里；审计轮识别无效通过（false pass）测试时也以本文档的完成定义为准。通用版本改写自 Mesh 的 `skill/testing/test-design-methodology.md`，接入具体项目时应补充本仓库的层级划分（如 T1–T5）与示例文件路径。

## 核心原则：模型 → 生成 → 预言机

逐例手写的测试只能稀疏采样组合状态空间（操作序列 × 状态 × 并发交错 × 恢复路径），bug 恰恰住在没被采到的罕见交错里。系统化的替代：

1. **建模**：显式写出状态空间（维度、操作、转移）。
2. **生成**：从模型生成用例（随机序列、转移矩阵、pairwise 组合），而不是逐例枚举。
3. **预言机判定**：用对任意输入都成立的判据（不变量、参照模型、幂等性、round-trip、收敛性）代替逐例手编期望值。

**稀缺资源是预言机，不是用例列表。** 投资在不变量检查器和参照模型上，之后生成用例是廉价的。

## 派生方法选型

| 被测对象 | 派生方法 |
|---|---|
| 纯函数 / reducer / normalizer / 文档操作 | 属性测试：生成操作序列 + 不变量预言机 |
| 显式状态机 | 状态 × 事件全转移矩阵（含未定义转移的格子，让隐式决策可评审） |
| 窄 API 的有状态组件 | 基于模型的命令序列：随机命令同时打在真实实现与平凡正确的参照模型上，每步断言观测等价 |
| 多因子守卫谓词 / 配置规则 | pairwise 覆盖数组，喂给表驱动用例；禁止手写全笛卡尔积、禁止每次运行随机采样 |
| 同步 / 提交 / 恢复边界 | 确定性故障注入模拟：真实客户端代码 + 种子化虚拟延迟 + begin-reject / commit-reject / ack-lost 注错，静默态断言全套不变量 |
| 定时逻辑（debounce / 调度） | 抽出纯调度器 + 可注入时钟，虚拟时钟属性套件 |
| 整个编辑/操作面健壮性 | 种子化 monkey 走真实操作路径 + 结构预言机 |
| 昂贵的端到端用例选取 | 旅程矩阵（旅程类别 × 功能面）按覆盖缺口选取，优先补多特性压缩旅程和中途 kill/刷新/断连的 saboteur 巡演，而不是更多 happy path |

## 生成式套件的完成定义

一个属性/矩阵/模拟/monkey 套件要成为门禁，必须全部满足：

1. **测真实代码**：只 fake 窄外部边界（transport、时钟、digest），禁止在测试里重新实现被测行为再测副本。
2. **收缩安全的生成**：生成规范化意图并在应用前对当前状态实体化，任何收缩后的子序列仍然合法。
3. **预言机每步断言**，不只看终态：不变量为空、模型对应、幂等/round-trip。
4. **预言机阳性对照**：对每类违规人为破坏一次合法状态，断言检查器能报警；没有阳性对照的预言机可能空转通过。
5. **人工 mutation check 并在交付中声明**：破坏一次被测代码（去掉排序、丢掉 abort、绕过队列），确认套件以小反例失败，再还原。套件仍绿则先修套件。
6. **确定性且有界**：只用种子化随机；有界轮数与序列长度；失败时 seed + 收缩后反例足以复现。

## Bug → 模型反馈循环

补丁式测试会复发，除非逃逸的 bug 反哺模型。修复任何逃逸缺陷时必须回答：**模型缺了哪个维度、预言机缺了哪条不变量、还是生成器造不出这条失败序列**——然后扩展对应环节，让整类 bug 被覆盖。只有当 bug 确实超出所有模型范围时，才允许补一条裸回归用例，并说明理由。
