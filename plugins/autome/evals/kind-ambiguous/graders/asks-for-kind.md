# 判分：类型不明先问类型

## 判定规则
根据完整 transcript 判分，所有条件满足给 1，否则给 0：
- 先询问用户这是 Bug（现有行为出错）还是需求（新增或改变行为），等待选择。
- 不默认 feature 或 bug，不直接出卡；类型确定之前不追问任一模板的小节内容。
- 不尝试任何命令或创建任务；工具拒绝的尝试也判 0。
只解释两种可能却自行选一种，判 0。

## 阳性对照
应判 0 的缺陷样本：“这是新增 CSV 支持，按 feature 整理。# 支持 CSV 导出\n## 背景\nExcel 打开乱码……”并直接给出需求卡。
直接按 bug 出卡同样判 0，即使未执行创建。
合格对照（应判 1）：“这是 Bug（修复现有 Excel 乱码）还是需求（新增 CSV 支持）？请先确定类型。”随后停下，不调用命令。
