# 证明协议：从候选到可删

来源：reclaim-code-entropy 的「证明或否决」与「实施一次已证明的切割」，
dsh-find-simplifications 的消费者分级，社区死代码技能里的四种死法与回滚纪律。

## 1. 消费者分级

对候选的每个名字做穷尽搜索，把每个命中归入一类：

| 类别 | 定义 | 对删除的影响 |
|---|---|---|
| 生产 | 运行时真正加载的源码、配置、迁移、镜像、部署清单、运行脚本（档案 §0.4） | 有一个就否决，除非用户决定砍能力 |
| 非生产 | 测试、fixture、示例、文档、笔记、快照 | 不阻断；删候选时一并处理 |
| 模糊 | 既被测试又被脚本用的工具；动态入口可能触及的；兄弟仓库或下游可能引用的 | 先降级为「需要证明」；证明不了就保留 |

分级依赖档案 §0.4 与 §0.8。没有档案就先补档案，别凭目录名猜。

## 2. 四种「死」与各自的处理

| 死法 | 定义 | 处理 |
|---|---|---|
| 不可达 | 没有任何路径能调到 | 删 |
| 未使用 | 可调，但没人调 | 删 |
| 冗余 | 与一条活路径做同一件事 | 先把调用方指到活路径，再删 |
| flag 后休眠 | flag 一个发布周期都没翻过 | 先退役 flag，再删它的分支 |

风险高的先做软删除（标 deprecated、加一次性日志），观察一个周期再硬删。

## 3. 证明步骤

1. 穷尽搜索：符号、字符串、路径、配置键、环境变量、序列化字段、wire 名、CLI flag。
2. 命中分级（§1）。
3. 读调用方与被调用方，含动态分发路径。
4. 历史：`git log -S '<name>' --oneline`，看引入时的动机；找决策记录（ADR、设计文档、Agent Notes）。
   决策仍然成立就保留，并在报告里引用它。
5. 有状态或异步的候选：画所有权图——每个 sentinel、promise、取消路径、标志分别归谁拥有。
   映射到同一所有者的是镜像，各管一段的不是。
6. 说清删掉后失去什么能力。说不出「无」或具体能力的，还没证完。
7. 估净减少：文件、导出、依赖、状态、概念各减多少。只是把复杂度挪个地方的不算。
8. 找出「删错了会最先失败的最小检查」：一个测试、一条 lint、一个 typecheck、一次 grep。

## 4. 证据记录

```
[confidence: high|medium|low / risk: low|medium|high] <候选一句话>
evidence:  <生产消费者 0 个；非生产 N 个在 …；历史 …>
cut:       <具体删什么，到哪一层>
tradeoff:  <失去的能力或兼容性；没有就写「无可见行为变化」>
verify:    <删错了会最先失败的最小检查>
```

置信度说的是「消费者清单是否穷尽」；风险说的是「删错了的代价」。两者独立评。

## 5. 否决或降级的条件

- 有生产消费者。
- 动态可达性排除不了。
- 决策记录、来之不易的模式（仓库文档写明「曾经因为 X 付过代价」）仍然成立。
- 改动只是把复杂度挪到别处，API 面没变小。
- 太小、太不确定、超出范围——改成一条带标签的 TODO。
- 档案 §0.7 列出的有意重复与预留接缝，未经用户明确要求不提议。
- 最近几周刚加的代码：它可能走在调用方前面。

## 6. 实施纪律

- 一次一个所有权边界。一个 batch 能一次回滚。
- 契约删到底：导出、类型、注册、构建入口、配套测试、文档引用。不留半截。
- 依赖替换（用已装包替代手写）要点名：那个包覆盖哪些行为、它的健康度、仓库依赖预算是否允许、
  净减少是否诚实（引入一个大包换掉 30 行不是净减少）。
- 不加 shim、别名、兼容层，除非有明确的对外义务。
- 并行 batch 时只 stage 自己改的文件，不 `git add -A`。
- 一个 PR 大致 400 行改动以内，超过就拆。

## 7. 验证纪律

1. 重新搜索被删的名字（含字符串与配置），确认零残留。
2. 先跑证据记录里的最小检查，再快检，再全检；专项按前置条件决定，不跑要写明。
3. 重跑当初产生候选的分析器，确认候选消失而不是被静音。
4. `git diff --check`，完整读 diff。
5. 对照公开面、持久化格式、线协议：可见行为有没有变。
6. 失败：回滚 batch 或修正证明。**绝不放宽断言、削弱类型、跳过测试。** 没有测试 / lint / typecheck 的仓库，
   在报告里明说，不默默跳过。
