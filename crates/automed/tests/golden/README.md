# 出仓前的 prompt 原文

`prompts/` 下这七个文件是**协议出仓之前**、由编译期常量拼出来的 prompt 原文，
用 `{slug}`、`{request}`、`{budget_line}` 三个占位符回填了会话相关的部分。

它们的用处只有一个：证明「把协议搬出二进制」这件事没有顺手改掉任何一个字。
`prompt_rendering.rs` 拿当前协议种子渲染同样的 prompt，逐字节对比这七份。

对比失败**不一定是 bug**。协议本来就是要演进的——改了 prompt 模板、发布了新版本，
这个测试当然会红。红了之后的正确做法是：确认改动是有意的，看一遍 diff，
然后把这里的文件更新成新的基准，并在提交信息里写清楚改了什么、为什么。

不要在没看 diff 的情况下直接覆盖。这个测试的价值全在「看一眼」上。
