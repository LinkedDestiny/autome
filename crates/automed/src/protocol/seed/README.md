# Loop 协议仓库

这是一个普通的 git 仓库，Autome 把它当成一个内置项目。里面是 Loop 的规则本身：
六个角色共同遵守的协议、每个角色的 prompt 模板、每轮简报抄哪些小节的映射，
以及说明「某一版协议应该让会话做出什么行为」的 eval 用例。

## 文件

| 文件 | 是什么 |
|---|---|
| `loop-protocol.md` | 六个角色共同遵守的规则。任务创建时整份复制进任务目录。 |
| `session-protocol.md` | 一次会话的边界：怎么开始、怎么结束、状态块长什么样。 |
| `prompts/*.md` | 每个角色的 prompt 模板。Autome 填 `{slug}`、`{budget_line}` 这些占位符。 |
| `brief-map.toml` | 角色 → 协议小节 的映射，决定每轮简报里抄哪几段。 |
| `evals/` | 行为用例。`behavioral` 类改动必须带一个，且要「改前红、改后绿」。 |
| `CHANGELOG.md` | 每个版本改了什么、依据是哪些任务的教训、预测哪个指标会怎么动。 |
| `contract.toml` | 内核契约区清单。**只是给人看的**，期望哈希存在二进制里。 |

## 版本

每次发布打一个 `protocol/vN` 标签。任务创建时把当时的协议全文复制到
`docs/<slug>/protocol/`，并记下 `protocol_ref`（标签 + 内容哈希）。会话读的是
任务目录里那份副本，不是这里——所以改这个仓库不会影响任何正在跑的任务，
而两台机器上同名标签内容不同这件事会由哈希暴露出来，不会悄悄地发生。

**回滚是向前的。** 版本页上的「回到此版本」不移动标签，而是生成一个内容相同的
新版本，并在 CHANGELOG 里追加一条 `kind: retire`。指标表里旧版本那几行仍然成立。

## 怎么改

不要直接在 `main` 上手改然后发布——那样没有评审、没有 eval、没有证据链。
在设置页点「改进 Loop」，Autome 会在这个仓库上开一个普通的 Loop 任务：
设计轮提改动、评审轮挑毛病、实现轮改文本并配 eval、审计轮跑 eval 门，
两道人工卡点是你。

有几样东西这条路也改不了，`autome protocol eval` 第一层会直接拒绝：

- 被 `<!-- kernel-contract: … -->` 包住的区域。内核解析的就是那些文本。
- 状态机、转换表、预算、守卫代码。那不是协议，那是 Autome 本身。
- `.autome/rules/`。项目规则走另一条路（面板上的「建议入规」卡片）。
