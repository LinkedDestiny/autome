# 会话协议

Autome 维护的会话边界，随版本刷新。

## 会话如何开始和结束

CLI 会话在任务 worktree 内运行；完成后结束，不要启动下一个会话。
Autome 按设计状态块调度，控制并行、暂停、角色与预算。

## 硬性边界

<!-- kernel-contract: boundaries -->
- 不修改 `.autome/` 下的任何内容，也不修改协议仓库。
- 不切换分支，不自己建或删 worktree，不推送远端。
- 工作目录以外的东西不改。单仓库项目里工作目录就是本任务的检出；工作区项目里它是
  一个装着若干检出的目录，**每个子目录是一个独立仓库**——在任一子目录里提交都可以，
  跨出工作目录就不行。
- 不修改用户主工作树（工作目录之外的仓库根目录内容）。
<!-- /kernel-contract -->

## 读文件的开销

- 同一文件每轮只读一次；超过 200 行分段读，避免重复占用上下文。
- 大量命令输出全文存 `.autome/output/`，只读头尾，例如：
  `cargo test > .autome/output/t.txt 2>&1; tail -20 .autome/output/t.txt`

## 状态块

设计文档 `<doc_dir>/<slug>.md` 的头部必须维护以下字段，格式严格：

<!-- kernel-contract: status-block -->
```text
status: 设计中 | 实现中 | 已完成 | 不可实现 | 协议失败
design-round: d/N
implementation-round: k/N
current-milestone: M-xx | 无
current-milestone-reopens: r
convergence-mode: normal | domain-review | milestone-review
next-action: <下一实现轮首先完成的具体工作；没有时写"无">
repos: <本任务要改动的仓库，逗号分隔；单仓库项目省略这一行>
```
<!-- /kernel-contract -->

`repos:` 只在工作区项目里有意义——那种项目的工作目录下是若干个各自独立的仓库。
**写下一个仓库名，就是请 Autome 为它建检出和分支**；你自己不要建 worktree、不要
切分支。只出现在这一行里的仓库才会被检出，也才会在合并时被合并。

这一行只增不减：后面的轮次发现还要动别的仓库，追加名字；**不要删掉已经在里面的**
——删掉不会撤销任何东西，只会让那个仓库的改动在合并时被漏掉。

里程碑用固定表格，Autome 按列读取：

<!-- kernel-contract: milestone-table -->
```markdown
## 里程碑

| ID | 状态 | 标题 | reopen | 领域 |
|---|---|---|---|---|
| M-01 | 已完成 | 购物车数据模型 | 0 | |
| M-02 | 待审 | 结算接口 | 1 | promo-case |
```

状态只有 `开放` / `待审` / `已完成` 三种。实现轮不得把里程碑标为 `已完成`，
只有审计轮独立复验通过才能关闭。
<!-- /kernel-contract -->

**`## 里程碑` 一节里只放这一张表格。** Autome 在这一节里按位置读表，多一张
表就可能读错——2026-09-16 有一轮在这一节中间写了张对比表，表头第一格是空的，
整份文档被判协议失败，任务停摆。逐轮证据写进 `<doc_dir>/evidence/`，
对比与说明写进那里，不要放在里程碑表所在的这一节。

`## Backlog` 与 `## 争议项` 两节用无序列表，每条以稳定 ID 开头。

**任一字段缺失或格式错误，Autome 一次即判协议失败并停下等人。** 不要猜测格式，
不要把状态块放进代码块，不要用其它写法表达同一件事。

## `协议失败` 是什么，不是什么

`status: 协议失败` 只表示无法使设计文档符合协议格式，任务会停下等人。
提交不上（权限或沙箱拒绝）时保留改动，记录「提交由 Autome 兜底」并正常结束。
拿不到某条验收证据时记录原因，保持应有的里程碑状态；发现了实现缺陷则退回 `开放` 并增加 reopen；
工具链不符时更新设计并说明理由。这些情况都不是协议失败，应留下记录让 Loop 继续。
